# 16 执行器细化设计(functional:Runner / Report / CookieStore / CLI)

> 层归属:**functional**。使用者:场景脚本作者(通过 CLI 间接使用)、CI 集成者。

**简单路径**(命令行视角,零配置):

```bash
php bin/ws-http run scenario.json        # 跑一个场景,失败 exit 1
# 复杂能力(多脚本聚合、JSON 报告供 CI、变量覆盖)全部是可选参数,见 §5。
```

> 范围:场景执行器(Runner)状态机、执行结果对象(StepResult/Report)、CookieStore、CLI 入口。
> 旧代码参考:`Automated/Bootstrap.php`(仅执行第一个请求的 break bug B4、`run()` 空壳、Task type 未消费);`CookieStore.php`(空壳)。

## 1. Runner:执行模型与状态机

### 1.1 执行流程

```
run(Scenario) :
  1. scope   ← 场景 variables 初始化
  2. cookies ← 按 settings.cookieStore 初始化 CookieStore
  3. report  ← new Report(scenario)
  4. for each step in steps:
       if report.shouldStop() → 记录 StepResult(skipped, reason="fail-fast") ; continue
       stepResult ← runStep(step, scope, cookies)
       report.add(stepResult)
  5. report.finalize(scope.snapshot()) → return report

runStep(step):
  http  → resolve(${var} 深替换,失败→failed 终止)
        → 合并配置:内置默认 < 场景 settings < 步骤覆盖(Timeout/proxy)
        → 应用 CookieStore(请求前注入,design/16 §4)
        → Request 发送(传输异常 → failed, code=101)
        → VarExtractor.extract(失败规则按 onMissing)
        → AssertionRunner.run(全部断言,不短路)
        → CookieStore.collect(从响应收集)
        → 判定步骤成败:传输失败 ∨ extract.failures 非空 ∨ 任一断言 failed
  delay → sleep(duration);结果 passed(不参与断言)
```

### 1.2 状态机(单步)

```
        ┌─────────┐   resolve 失败/传输失败/提取失败/断言失败
        │ pending │ ────────────────────────────────→ failed
        └────┬────┘
             │ 全部通过
             ▼
          passed

  skipped:failFast 终止后未执行的步骤(记录 reason,不计入失败数)
```

- **failFast=true**(场景默认):首个 failed 步骤后,后续全部 skipped;
- **failFast=false**:failed 后继续执行;后续步骤引用失败步骤未产出的变量时,按 design/15 §4.3(未定义变量)自然失败——这是预期行为,报告可追溯;
- 引擎内部**不抛异常**:仅 `ScenarioParser` 解析失败(design/14 V1–V9)抛 `AutomatedException`(根本无法执行)。

## 2. Runner API

```php
final class Runner
{
    public function __construct(
        private RequestFactory $requestFactory,   // 依赖注入点:测试时注入 mock
        private ExpressionEvaluator $evaluator,
        private Clock $clock = new SystemClock,   // 可注入时间源(报告计时)
    );

    public function run(Scenario $scenario): Report;

    /** 单步执行(公开供调试/单测) */
    public function runStep(Step $step, VariableScope $scope, CookieStore $cookies): StepResult;
}
```

- `RequestFactory` 接口:`create(RequestOptions $options): Request`——**引擎与 L1 解耦的关键**,单测中 mock 掉真实 HTTP;
- Runner 不持有可变状态(每次 run 全新局部变量),单实例可跑多场景。

## 3. 结果对象

### 3.1 StepResult

```php
final class StepResult
{
    public readonly string $stepId;
    public readonly string $stepName;
    public readonly string $stepType;      // http | delay
    public readonly StepStatus $status;    // pending|passed|failed|skipped
    public readonly ?string $failReason;   // 失败根因摘要(一句话)

    // http 步骤独有
    public readonly ?RequestSummary $request;   // method/url/headers(脱敏后,§3.3)
    public readonly ?int $statusCode;
    public readonly ?float $durationMs;         // 本步骤耗时(含断言/提取)
    public readonly ?string $responseExcerpt;   // rawBody 前 2KB(报告预览)

    /** @var AssertionResult[] */
    public readonly array $assertionResults;    // design/12 §5
    /** @var string[] */
    public readonly array $warnings;            // extract skip/default 等
    /** @var array<string,mixed> 本步骤新提取的变量(名→值) */
    public readonly array $extractedVariables;
}
```

### 3.2 Report

```php
final class Report
{
    public readonly string $scenarioId;
    public readonly string $scenarioName;
    public readonly \DateTimeImmutable $startedAt;
    public readonly ?\DateTimeImmutable $finishedAt;

    /** @return StepResult[] 按执行顺序(含 skipped) */
    public array $steps;

    public int $passedCount(): int;
    public int $failedCount(): int;      // 不含 skipped
    public int $skippedCount(): int;
    public bool $isSuccess(): bool;      // failedCount === 0
    public float $totalDurationMs(): float;

    /** 终态变量快照(design/15 §5) */
    public array $variables;

    public function toArray(): array;    // JSON 报告形态
}
```

`toArray()` 即 JSON 报告契约(CLI `--format=json` 的输出,也是 CI 集成的接口),结构:

```jsonc
{
  "scenario": { "id": "...", "name": "..." },
  "startedAt": "2026-09-10T14:30:00+08:00",
  "durationMs": 1234,
  "summary": { "passed": 3, "failed": 1, "skipped": 1, "success": false },
  "variables": { "token": "...", "ktvId": "..." },
  "steps": [
    {
      "id": "login", "name": "...", "type": "http", "status": "passed",
      "request": { "method": "POST", "url": "..." },
      "statusCode": 200, "durationMs": 210,
      "extractedVariables": { "token": "..." },
      "assertions": [ { "source": "status", "op": "eq", "expected": 200, "actual": 200, "passed": true } ],
      "warnings": []
    }
    // { "id": "submit", "status": "skipped", "reason": "fail-fast after step 'wait'" }
  ]
}
```

### 3.3 敏感信息脱敏

报告与响应摘录中的 `Authorization` 头、`cookie` 头、auth.password/auth.token 字段一律替换为 `***`(长度保留),报告可安全归档。

**变量快照脱敏**(S8 补充):`variables[].secret: true` 声明的变量(design/15 §2.1.1),其值在 Report/StepResult 输出中同样替换为 `***` —— 断言失败消息中若引用该值亦同。执行语义不受影响(引擎内部用真实值)。

## 4. CookieStore

```php
interface CookieStore        // 即 core Contract\CookieStoreInterface
{
    /** 请求前:返回应注入该 URL 的 Cookie 请求头值,无则 null */
    public function cookieHeaderFor(string $url): ?string;

    /** 响应后:从 Set-Cookie 头收集 */
    public function collectFrom(Response $response, string $url): void;
}
```

| 实现(settings.cookieStore) | 行为 |
| --- | --- |
| `memory`(默认) | 进程内 jar:按 cookie 名存储,作用域 = 主机;发送时按 URL 主机匹配回放;`expires` 过期剔除;**不做域名后缀匹配**(单场景测试用途足够,避免过度实现) |
| `none` | 空实现 |
| `file:<path>` | memory 基础上,场景结束时以 Netscape cookie 文件格式落盘;场景开始时若文件存在则加载 |

- 与显式 `${loginCookie}` 提取并存:CookieStore 管传输层 cookie(FILE+JAR 语义),extract 管业务变量(如需要把 cookie 值放进自定义头);二者不互斥;
- Runner 在步骤成功发起请求后调用 collectFrom(无论状态码,4xx 响应的 Set-Cookie 也可能有效)。

## 5. CLI 入口

```
bin/ws-http run <script.json...> [options]

选项:
  --format=text|json     报告格式,默认 text
  --report-out=<file>    报告写入文件(默认 stdout;--format=json + --report-out 供 CI)
  --no-fail-fast         覆盖场景 failFast=false
  --var name=value       覆盖/追加初始变量(可重复;优先级高于脚本 variables)
  --stop-on-parse-error  多脚本时遇解析错误立即退出(默认继续执行其余脚本)

退出码:0 = 全部场景 success;1 = 任一场景存在 failed;2 = 解析错误
```

text 输出示例:

```
Scenario 夜点娱乐-预订流程 (scenario-yedian-001)
  ✓ login    微信用户登录获取 token        200  210ms
  ✓ userinfo 根据 token 获取用户信息        200   95ms
  ✗ search   按名称搜索 KTV               200  134ms
       assertion failed: json $.total gt 0 → actual: 0
  - wait     等待                          skipped (fail-fast after step 'search')
  - submit   提交订单                       skipped

Summary: 2 passed, 1 failed, 2 skipped (439ms)
```

## 6. 依赖注入与可测性

| 注入点 | 测试用途 |
| --- | --- |
| RequestFactory | mock HTTP 层:返回预制 Response,验证 Runner 编排逻辑(resolve→发送→提取→断言→判定) |
| Clock | 延时步骤不真 sleep:mock Clock 累计时长 |
| CookieStore | 自定义 jar 行为注入 |

引擎单元测试不需要真实网络;真实网络仅出现在 Integration 层。

## 7. 测试要点

| 用例组 | 覆盖 |
| --- | --- |
| 编排 | resolve→发送→提取→断言→判定 全链(mock factory);配置三级合并(内置<场景<步骤) |
| failFast | 首败终止 + 后续 skipped;failFast=false 继续执行 |
| 状态判定 | 传输失败/提取 fail/断言失败/全部通过 四类进入 failed/passed 的映射 |
| Report | passed/failed/skipped 计数;toArray 结构快照;脱敏(Authorization/cookie → ***) |
| CookieStore | memory jar 收集→回放→过期;none 空实现;file 持久化往返 |
| CLI | 退出码 0/1/2;--var 覆盖优先级;多脚本聚合 |
| 对照 | 修复 B4 的行为验证:多步骤场景全部步骤被顺序执行 |
