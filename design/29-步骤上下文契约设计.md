# 29 步骤上下文契约设计(functional:retry / until / when)

> 层归属:**functional(Automated)**。使用者:场景脚本作者(异步接口、不稳定依赖、条件流程的测试)。
> 背景:design/14 开篇点名的 v2 遗留契约缺口——"缺失定义:断言操作符、提取失败策略、**步骤上下文(如重试、跳过)无契约**"。本文补齐步骤上下文三能力:重试(retry)、轮询等待(until)、条件执行(when)。

**简单路径**(场景脚本作者视角,三个能力各一行声明):

```jsonc
{ "type": "http", "id": "submit", "url": "...", "method": "POST",
  "retry": { "max": 2, "interval": "2s" } }              // 偶发抖动的接口,失败自动重发
```

```jsonc
{ "type": "http", "id": "pollJob", "url": ".../job/1", "method": "GET",
  "until": { "timeout": "60s", "interval": "3s",
             "assertions": [ { "source": "json", "path": "$.status", "op": "eq", "expected": "done" } ] } }
```

```jsonc
{ "type": "http", "id": "deleteDraft", "url": "...", "method": "DELETE",
  "when": { "var": "hasDraft" } }                        // 变量 falsy 时跳过本步
```

> 简单路径使用者只需要:在 step 上加 `retry` / `until` / `when` 三个可选字段之一。语义、校验、状态机变化见 §2–§5。

## 1. 定位与边界

### 1.1 是什么

步骤级**执行上下文**:不改变步骤的内部语义(发送→提取→断言),只在外层加三种控制——

| 能力 | 声明 | 解决什么 |
| --- | --- | --- |
| `retry` | 失败后重发 | 偶发失败(网络抖动、限频、最终一致写入)导致的误报 |
| `until` | 轮询直到断言通过 | 异步任务的完成等待(提交后轮询状态) |
| `when` | 条件不满足则跳过 | 同一脚本跑多种环境/数据时的条件分支(如"有草稿才清理") |

### 1.2 不是什么(防过度设计,写具体代价)

- **不做场景级/数据集级并行**(2026-11-04 用户定调):PHP 单进程串行模型与场景的线性变量流一致,并行的收益(缩短套件时长)归外部进程编排(CI 起 N 个进程消费 JSON 报告聚合),库内核保持串行——否则变量作用域分叉/合并语义侵入 Runner,复杂度曲线抬高简单路径,违反总则;
- **不做 if/else/循环编排**:分支让场景不可线性审读(报告失去"从上到下即执行序"的性质),调试成本高于收益;`when` 只覆盖"单步跳过"这一真实高频需求;
- **不做步骤级跳转/重定向流程**(goto/sub-flow):场景复用归"套件/子流程"议题,触发条件未满足(无 ≥2 个真实跨项目复用场景),不立项;
- **retry 不做指数退避/Jitter**:引擎侧重试面向测试抖动消除,节奏参数 `interval` 固定即可;指数退避是 SDK/传输层(design/28 Transport 已有)语义,不重复建设。

### 1.3 与 design/22(pause/poll)的关系

严格区分,**不合并**:

| | design/22 `pause` + `poll:<name>` | 本文 `until` |
| --- | --- | --- |
| 目的 | **等一个值**(验证码/凭据)写入 VariableScope | **等一个状态**(断言通过) |
| 载体 | pause 步骤(挂起取值) | http 步骤(重复执行同一请求) |
| 判定 | ValueResult got/pending/missing | 断言子集 passed/timeout |

poll 的取值逻辑复用 extract 注册表,until 的判定复用断言注册表——**同一"pending-等待-超时"心智,两个正交入口**。

## 2. Schema v2 追加:三个可选字段

全部为 http 步骤的**可选**字段,delay/pause 步骤不支持(语义不适用:delay 本身就是等待,pause 的成败由取值策略决定)。未知字段拒绝(严格模式,与 V3 一致)。

### 2.1 retry

```jsonc
"retry": {
  "max": 2,              // 必填,1–5(整型;额外尝试次数,总执行次数 = max + 1)
  "interval": "2s"       // 可选,默认 "1s";§4.1 时间格式,上限 60s
}
```

- **触发**:一轮完整执行判定为 failed(传输异常 / extract onMissing=fail / 断言失败)→ 等待 interval → 重发;
- **不触发**:resolve 失败(脚本错误,如未定义变量)——配置错误重试无意义,首次失败即 failed;
- **成功判据**:任一轮全绿即 passed,`attempts` 记录实际执行轮数;
- **CookieStore 副作用**:每轮真实发送,collectFrom 每轮照常执行(与正常多步请求无异);
- **与 failFast**:failFast 只看最终状态——重试耗尽才 failed,才触发 failFast 终止。

### 2.2 until

```jsonc
"until": {
  "timeout": "60s",      // 必填,§4.1 时间格式,上限 300s(与 delay 上限一致)
  "interval": "3s",      // 可选,默认 "2s",上限 60s
  "assertions": [ ... ]  // 必填,非空;AssertRule[](design/12 §5 同构)
}
```

- **执行语义**:发送请求 → 只跑 `until.assertions`(不跑步骤常规 `assertions`,不跑 `extract`)→ 未通过则等 interval 重发,直至 timeout;
- **通过后**:回到正常流程——执行常规 `assertions` 与 `extract`(用**最后一轮响应**),再判定步骤成败。即 until 是"门槛",不是"替代";
- **超时**:最后一轮断言仍未通过 → 步骤 failed,failReason 含 `"until timeout after 60s, 21 attempts, last: <末轮断言失败消息>"`;常规 assertions/extract 不执行;
- **传输异常**:计入本轮失败,等 interval 重试(异步任务轮询中偶发 502 不该终止等待);**连续传输异常不特判**(timeout 兜底,不引入两套上限);
- **resolve 失败立即 failed,不轮询**(与 retry §2.1 同款逻辑):未定义变量等脚本错误轮询无意义,首次失败即 failed;
- **attempts 记录**同 retry。

### 2.3 when

```jsonc
"when": { "var": "hasDraft" }        // 最小形态(首版唯一形态)
```

- **语义**:`VariableScope::get(var)` 已定义且值 truthy(PHP 语义:非 null/非 false/非 0/非 ''/非 [] /非 '0')→ 执行;否则**跳过本步**;
- **跳过形态**:StepResult(status=skipped,reason=`"when: var 'hasDraft' is falsy"`)——**复用既有 skipped 状态**(failFast 已用),skipped 不计入失败、不触发 failFast、后续步骤照常执行;
- **首版不做路径/操作符形态**(`when: { "$.x": {...} }`):变量存在性判断覆盖"环境差异"主场景;JSONPath 条件 = 先 extract 到变量再 when,表达力等价,无需新 DSL。若真实需求出现,追加形态是字段扩展,无破坏。

## 3. 对象映射与 Runner 状态机

### 3.1 PHP 对象

```php
// Step 上下文值对象(functional 层,HttpStep 可选属性)
final class RetryPolicy      { public function __construct(public readonly int $max, public readonly int $intervalMs); }
final class UntilPolicy      { public function __construct(public readonly int $timeoutMs, public readonly int $intervalMs, public readonly array $assertions); }
final class WhenCondition    { public function __construct(public readonly string $var); }
```

### 3.2 Runner 执行模型(runStep 外层包装,主循环骨架不动)

```
runStep(step):
  when   → 条件不满足 → StepResult(skipped, reason) → return(不发送)
  retry? → 外层 for attempts ∈ [0..max]:
             result = runOnce(step)                 # 既有单次执行逻辑(resolve→发送→提取→断言)
             until? → 由 runOnce 内部按 §2.2 轮询(见 3.3)
             passed → break
             还有剩余 → sleep(interval) → 继续下一轮
           最终 result 进 Report(attempts 一并记录)
```

- 三者可组合:retry + until = 每轮重试内部自行轮询(**单轮 until timeout 即该轮失败,进入下一次 retry;总时长上界 = (max+1) × timeout,脚本作者可预期**);when + retry = 条件满足才进入重试循环;
- **Clock 注入沿用 design/16**(retry interval / until interval+timeout 均经 Clock,单测不真 sleep)。

### 3.3 StepResult / Report 契约追加(向后兼容,可选字段)

```jsonc
// StepResult 追加(仅 retry/until 步骤出现):
"attempts": 3,          // 实际执行轮数(无 retry/until 时 = 1,不输出)
"context": "retry"      // "retry" | "until"(报告展示用)
```

- JSON 报告契约追加可选字段,消费端(渲染器/CI)不感知新字段照常工作;
- 脱敏规则不变(attempts/attempt 计数不含敏感数据)。

## 5. 错误码

不新增错误码段:配置错误走既有 402(V20–V23);运行期失败语义复用既有(传输 101 / 断言 301–305 / 提取 405),until 超时是**步骤失败**而非新异常类,failReason 文本区分。引擎"内部收集不抛异常"原则不变。

## 6. CLI

**零改动**。三个能力全部是场景 JSON 声明,CLI 既有 `run`(参数、退出码、报告输出)原样承载;text/json 渲染器在步骤行追加 attempts 展示(如 `✗ pollJob  轮询任务状态  200  63.2s (21 attempts)`),不换版式。

## 7. 与既有设计的衔接

- design/14(Schema):§2 字段契约并入 http 步骤定义;V20–V23 并入 V 序列;§4.1 时间解析器共用;
- design/12(断言):until.assertions 复用 Assertion/fromArray/Comparison 全链,零改动;
- design/15(变量):when 只读 VariableScope(get/has);until 通过后回到正常单步语义——**沿用 design/16 §1.1 既有顺序(extract → 常规断言),用末轮响应**,不改变既有产出顺序;
- design/16(执行器):runStep 外层包装;StepResult 追加可选字段;Clock 注入复用;
- design/22(pause):§1.3 划界表互相引用,poll/until 心智统一、入口分离;
- design/23(Dataset):正交——每条记录独立享有 retry/until/when 语义,无交互。
