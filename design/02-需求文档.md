# 02 需求文档(PHP 7.4 重构功能基线)

> 本文档按模块整理 ws-http 重构后的完整功能需求。定位:**保持现有对外能力(API 兼容层可选),内部全面现代化,并补齐 Automated 引擎未完成部分**。
> 约定:术语「请求配置」指 Request 实例上可叠加的超时/头/认证/代理等;「响应断言」指 Watcher;「场景脚本」指 Automated JSON。

## 0. 总体需求

| 编号 | 需求 |
| --- | --- |
| N-01 | 目标运行环境 PHP 7.4(充分利用:严格类型声明、箭头函数、null 合并、spread、`typed properties`),不要求向下兼容 5.x |
| N-02 | 运行依赖仅 `ext-curl`、`ext-json`(composer.json 声明),PHP 7.4 自带;移除 PECL http 依赖 |
| N-03 | PSR-4:`Ws\Http\` → `src/`;保留 `toohamster/ws-http` 包名与 MIT 协议 |
| N-04 | 清除全部遗留调试代码、外部隐藏依赖(`\Ws\Env`)、未使用代码 |
| N-05 | 测试框架统一为 PHPUnit(≥9),所有模块有单元测试;网络依赖型用例可用 mock 或标记 skip |
| N-06 | 所有异常继承统一的 `Ws\Http\Exception` 体系,异常消息包含 curl errno/错误码等定位信息 |

## 1. 模块 A:HTTP 客户端(Request)

### A1 实例与生命周期

| 编号 | 需求 |
| --- | --- |
| A1-1 | `Request::create(?string $id)` 按 id 的命名实例池,兼容现用法;`Request::new()` 创建全新实例 |
| A1-2 | 支持 `clone` 与配置快照(便于同一配置派生多个请求) |
| A1-3 | 可通过 `getOpt()/getHeaders()` 等读取当前配置(现状完全不可读,不利于调试与测试) |

### A2 请求方法

| 编号 | 需求 |
| --- | --- |
| A2-1 | 快捷方法:`get/head/options/connect`(参数拼 query string)、`post/delete/put/patch/trace`(参数作 body),签名与现在一致:`($url, array $headers = [], $param = null)` |
| A2-2 | `send(string $method, string $url, $body = null, array $headers = [])` 支持任意标准/自定义 HTTP 方法(配合 `Method` 常量) |
| A2-3 | GET 的数组参数经 `buildHTTPCurlQuery` 拍平多维结构(`a[b]=c`),兼容 CURLFile 对象 |
| A2-4 | URL 自动编码(`encodeUrl`:query 重编码、中文 key 安全) |
| A2-5 | 默认头合并规则保留:无 UA 补 `ws-http/2.0`;无 Expect 置空避免 100-continue;头名统一小写发送 |
| A2-6 | 默认跟随重定向 ≤10 次;可配置关闭/修改上限(`maxRedirects`) |

### A3 请求配置(逐项保留)

| 编号 | 配置 | 需求 |
| --- | --- | --- |
| A3-1 | `jsonOpts($assoc,$depth,$options)` | 控制响应 JSON 解析 |
| A3-2 | `timeout($s)` / `timeoutMs($ms)` | 保留 NOSIGNAL 规避;默认超时改为 **30s**(现状无限等待) |
| A3-3 | `verifyPeer/verifyHost/verifyFile` | SSL 校验,默认开启;`caBundle()` 支持指向自定义 CA;默认用系统 CA(不再内置过期证书包) |
| A3-4 | `defaultHeader(s)/clearDefaultHeaders` | 缺省请求头 |
| A3-5 | `curlOpt(s)/clearCurlOpts` | 透传任意 cURL 选项,优先级:本次显式 > 实例 curlOpt > 内置默认 |
| A3-6 | `cookie($str)` / `cookieFile($path)` | 字符串与文件 cookie |
| A3-7 | `auth($user,$pass,$method=CURLAUTH_BASIC)` | CURLAUTH 全系 |
| A3-8 | `proxy($addr,$port,$type,$tunnel)` / `proxyAuth(...)` | HTTP/HTTP1.0/SOCKS4/4A/5/5H + 隧道 + 代理认证 |
| A3-9 | `Body::json/form/multipart/file` | 请求体构造器:`json` 自动补 `Content-Type: application/json`(修复 B6);`file` 仅返回 `CURLFile`(删旧式 `@` 兼容) |

### A4 响应与错误处理

| 编号 | 需求 |
| --- | --- |
| A4-1 | `Response` 保留公共属性:`code / curl_info / headers / body / raw_body`;新增只读便捷方法:`isOk()`(2xx)、`header($name)`(大小写不敏感取头,修复 B8) |
| A4-2 | 响应头解析:同名多值合并数组、状态行存 `headers[0]`(或独立 `$statusLine`);继续不依赖 PECL |
| A4-3 | JSON 自动解析:Content-Type 含 `application/json` 且解析成功时填充 `body`;解析失败时 `body=false` 且可取 `jsonError()` |
| A4-4 | cURL 传输错误(连接失败/超时/DNS 等)抛 `Ws\Http\RequestException`(含 errno、error、url);HTTP 4xx/5xx **不**抛异常,由调用方/断言处理 |

## 2. 模块 B:响应断言(Watcher)

| 编号 | 需求 |
| --- | --- |
| B-01 | `Watcher::create(Response)` + 链式断言,失败抛 `Watcher\Exception`,异常消息含期望值与实际值 |
| B-02 | `assertStatusCode(int)` |
| B-03 | `assertTotalTimeLessThan(float)` |
| B-04 | `assertHeadersExist(array $names)` |
| B-05 | `assertHeaders(array $kv)`:精确匹配(值支持数组任一匹配);索引数组退化为 B-04 |
| B-06 | `assertBody($x, bool $regex = false)`:特殊值 `IS_EMPTY` / `IS_VALID_JSON`;包含匹配(**修复 B1 参数顺序**);正则模式 |
| B-07 | `assertBodyJson($expected, $detail=false)`:宽松比较可选 var_export 详情 |
| B-08 | `assertBodyJsonFile($file, $detail=false)`:用 `JSON_PRETTY_PRINT` 比对(替换手写 prettyPrint) |
| B-09 | 新增(自动化引擎需要):`assertBodyJsonPath(string $path, $expected, string $op)`,支持 `list[0].xktvid` 式点路径与操作符 `eq/ne/gt/lt/ge/le/not_null/contains` |
| B-10 | 断言头取值大小写不敏感 |

| --- | --- |
| C-01 | `ARequest` 全 static 代理到 `Request::create('default')`,方法集与实例一致 |
| C-02 | 修复 `verifyHost` 误调 `verifyPeer`(B2) |
| C-03 | 作为兼容层保留;文档标注推荐使用实例方式 |

## 4. 模块 D:Automated 场景自动化引擎(补齐未完成部分)

### D1 场景脚本(JSON Schema)

```jsonc
{
  "id": "...", "name": "...",
  "type": 1,                       // 1=关联业务(任一请求失败即终止) 2=非关联(继续执行)
  "body": {
    "vars":   [ {"name": "token", "value": "1"} ],
    "requests": [
      { "id": "...", "type": 1,    // HTTP 请求
        "name": "...", "url": "...", "method": "GET|POST|...",
        "timeout": "15s|500ms",
        "header": { "K": "V", "K2": "${var}" },
        "authorization": { "type": "Basic", "user": "...", "password": "..." },
        "proxy": { "type": "http|socks5|...", "address": "...", "port": "...", "tunnel": false,
                    "auth": {"user":"...","password":"...","method":"Basic"} },
        "dataMode": "params|urlencoded|raw-json|raw-xml|raw-textxml|raw-html|raw-text",
        "data": [ {"key":"k","value":"${var}","type":"text"} ] | { "value": "..." },
        "postProcessors": [
          { "type": "setVar", "setVar": [
              {"match":"json|header","attr":"list[0].xktvid|Set-Cookie","var":"bookingKtvId"} ] },
          { "type": "asserts", "asserts": [
              {"match":"status|json|header","attr":"...","method":"eq|ne|gt|lt|ge|le|not_null|contains","expect":"..."} ] }
        ] },
      { "id": "...", "type": 2, "delay": 3 }   // 延时秒
    ]
  }
}
```

### D2 功能需求

| 编号 | 需求 |
| --- | --- |
| D-01 | 脚本解析:JSON → `Task` → `Task\Body` → `Task\Request`,严格校验必填字段与枚举值,给出含字段名的清晰错误 |
| D-02 | 变量系统:`vars` 初始化;`${var}` 占位在 url/headers/data/authorization/proxy/timeout 中递归替换;`setVar` 从响应提取回写后,**后续请求**立即可用 |
| D-03 | 变量提取:`match=json` 支持点路径(含数组下标);`match=header`;`match=raw_body`;提取失败按 Task type 决定是否终止 |
| D-04 | 断言:status / json path / header,操作符 eq/ne/gt/lt/ge/le/not_null/contains;失败消息含请求 id、名称、期望与实际 |
| D-05 | 执行循环:按序执行全部请求(**修复 B4 的 break**);type=2 延时;每步产出执行记录 |
| D-06 | 失败策略:Task type=1 时任一请求异常/断言失败即终止并标记失败;type=2 时记录失败继续 |
| D-07 | 支持的 dataMode 与 Content-Type 自动映射同现状(params/urlencoded/raw-*),`raw-binary` 明确抛不支持异常;file 类型参数映射 `CURLFile` multipart |
| D-08 | authorization:`Basic` 走 `auth()`;其余类型将 `authorization.body` 作为 Authorization 头(修复 B3 条件反转) |
| D-09 | proxy:类型字符串 → CURLPROXY_* 映射,含 auth(修复 B3) |
| D-10 | timeout:字符串 `15s`/`500ms` 解析,非法回退默认 30s |
| D-11 | 执行报告:每请求记录(请求摘要、状态码、耗时、断言结果、提取的变量),最终汇总 pass/fail;支持输出为文本/JSON |
| D-12 | `CookieStore`:实现请求间 cookie 传递(基于 cookieFile 或内存 jar,由脚本配置) |
| D-13 | 入口:`Bootstrap::run(array $tasks): Report` 与 CLI 脚本 `bin/ws-http run <script.json>`(exit code 0/1) |

## 5. 非功能需求

| 编号 | 需求 |
| --- | --- |
| Q-01 | 全代码库 PHP 7.4 严格类型(`declare(strict_types=1)`),public API 类型签名完整 |
| Q-02 | PHPStan level ≥ 6 通过;PHP-CS-Fixer(MAJORPSR12)通过 |
| Q-03 | 单元测试覆盖:URL 编码/参数拍平、头合并与解析、JSON body 解析、全部断言、变量替换与提取、脚本解析与执行编排(mock HTTP 层);集成测试对 httpbin.org 等公网服务,CI 中可 skip |
| Q-04 | README 重写:PHP 7.4、安装、Request/Watcher/Automated 三大用法、差异说明(如 UA 版本号、默认超时、CA 来源) |
| Q-05 | 兼容层承诺:`Request/ARequest/Response/Body/Watcher` 的现有公开方法签名不变(仅内部重写 + 修复 bug 行为) |

## 6. 明确不做(Out of Scope)

- 不引入 Guzzle 等第三方 HTTP 库,仍基于原生 cURL(保持"轻量"定位);
- 不支持 HTTP/2 推送、异步并发请求(可作为 2.x 方向);
- 不兼容 PHP < 7.4,不保留 `@file` 上传旧语法与 PECL http 分支;
- Automated 不做 UI,仅 JSON + CLI。
