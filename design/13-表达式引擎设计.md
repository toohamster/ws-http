# 13 表达式引擎细化设计(functional:Ws\Http\Expression)

> 层归属:**functional**(被断言器与变量提取器使用,使用者通常不需要直接接触)。

**简单路径**——以下基础文法覆盖 90% 的实际用法:

```
$.list[0].xktvid                ; 点路径 + 索引
$.data.taocaninfo.roomtype[*].id  ; 通配
$.items[?(@.status == "active")].name  ; 过滤(深水区)
```

**简单路径使用者只需要记住**:点路径 + `[数字]`,`$` 可省略。其余文法(切片/联合/正则过滤)是"复杂的事情必须可能"的部分,需要时查 §2。

> 范围:JSONPath 子集的文法、解析器、求值语义、错误处理。**断言(source=json)与变量提取(match=json)共用本引擎**,是整个库的"单一事实来源"。

## 1. 目标与非目标

**目标**:
- 覆盖场景脚本 v1 中出现过的全部路径形态(如 `list[0].xktvid`、`data.taocaninfo.roomtype[0].id`);
- 提供脚本编写所需的常用扩展:多结果收集、过滤、切片、正则匹配;
- 语法可静态校验(解析期发现错误,而非求值期)。

**非目标**(明确不支持):
- `..` 递归下降、`$..book[?(@.price<10)]` 完整 JSONPath 规范;
- 脚本表达式/算术运算(`@.length-2` 之类);
- 指针写回(引擎只读)。

选型理由:自己实现 300 行以内的小型求值器,而非引入 `flow/jsonpath` 等依赖(总架构约束:零外部 require)。

## 2. 形式文法(EBNF)

```
expression     = root , path-step* ;
root           = "$" ;                          ; "$" 可省略:"a.b" ≡ "$.a.b"
path-step      = "." member
               | "." wildcard                   ; ".*"
               | "[" selector , { "," , selector } , "]" ;
member         = identifier | quoted-string ;
identifier     = ( ALPHA | "_" ) , { ALPHA | DIGIT | "_" | "-" } ;
wildcard       = "*" ;
selector       = index
               | slice
               | filter ;
index          = [ "-" ] , DIGIT , { DIGIT } ;  ; 负索引从尾部计数
slice          = [ index ] , ":" , [ index ] , [ ":" , [ index ] ] ;  ; start:end:step,step 可负
filter         = "?" , "(" , filter-expr , ")" ;
filter-expr    = "@" , ( comparison | existence ) ;
existence      = "." , member-path ;            ; @.attr 非空即真
comparison     = "." , member-path , comp-op , literal ;
comp-op        = "==" | "!=" | ">" | ">=" | "<" | "<=" | "=~" ;
member-path    = member , { "." member } ;
literal        = number | quoted-string | "true" | "false" | "null" ;
```

词法单元:`$ . [ ] * , : ( ) ? @ == != >= <= > < =~`、identifier、number(int/float)、quoted-string(单双引号,支持 `\'` `\"` `\\` 转义)。

**合法表达式示例**:

```
$.list[0].xktvid
list[0].xktvid                    ; $ 省略
$.data.taocaninfo.roomtype[*].id
$.items[?(@.status == "active")].name
$.items[?(@.price >= 100)].id
$.list[-1]                        ; 末元素
$.list[0:3]                       ; 切片
$.headers[*].name                 ; 通配
$["weird-key"]                    ; 带特殊字符的键
$.a.b[?(@ =~ /^ktv-.*$/)].id      ; 正则过滤
```

## 3. 求值语义

### 3.1 基本规则

1. 求值输入:根数据(`Response->body` 的解析结果,或变量值)+ 表达式;
2. 每个步骤的中间结果是**节点集合**(可能 0/1/N 个),最终结果是集合;
3. **取值包装**:`evaluate()` 返回 `EvaluationResult`,调用方按需取 `first()` 或 `all()`:
   - 断言、setVar 单值提取 → `first()`;
   - 收集型提取(setVar 声明 multiple)→ `all()`。

```php
final class EvaluationResult
{
    /** @return mixed[] 所有匹配节点 */
    public function all(): array;
    public function first(): mixed;        // 空集返回 null
    public function firstOrNull(): mixed;  // 同上(语义别名)
    public function count(): int;
    public function isEmpty(): bool;
}
```

4. **空集不是错误**:求值正常完成但无匹配 → `EvaluationResult` 为空,`first()` 为 null;是否算失败由调用方语义决定(断言 → fail;提取 → 看 design/15 的 on_missing 策略)。只有**语法错误**抛 ExpressionException。

### 3.2 各步骤求值规则

| 步骤 | 语义 |
| --- | --- |
| `.member` | 当前集合每个节点:map 为对象取属性;节点是数组且 member 为数字串时按索引;不存在 → 从集合中剔除(不报错) |
| `.*` | 当前集合每个节点展开为全部子值(对象为值集,数组为元素集) |
| `[n]` | 数组索引;负数从尾部(-1 为末元素);越界 → 剔除 |
| `[n:m(:s)]` | 切片,Python 语义;默认 start=0、end=长度、step=1 |
| `[a,b,…]` | 联合:多个 selector 结果按序合并 |
| `[?(expr)]` | 对当前集合每个**数组元素/对象属性值**求 filter-expr,真值保留;`@` 代表当前元素 |
| `@.path` (existence) | 属性存在且值非 null/空串 → 真 |
| `@.path op literal` | 按值比较;`=~` 期望正则字面量(含定界符) |

### 3.3 类型不匹配处理

| 情形 | 行为 |
| --- | --- |
| 对象上取 `[n]` 索引 | 剔除该节点 |
| 数组上取 `.member` | member 为纯数字 → 按索引;否则剔除 |
| 标量上继续下钻 | 剔除 |
| `[?(...)]` 作用于标量集合 | filter 对标量本身求值(`@` 即元素值;`@.path` 恒假) |

**设计取向:宽容求值**——一切结构性不匹配都是"无匹配",不抛异常;这使 `$.a.b.c` 在任意残缺数据上都是安全的,简化脚本编写。

## 4. API 规格

```php
final class ExpressionEvaluator
{
    public function __construct();                       // 无状态,可单例

    /** 解析 + 求值;语法错误抛 ExpressionException(201) */
    public function evaluate(mixed $data, string $expression): EvaluationResult;

    /** 仅静态校验(解析期检查),供场景脚本加载时预检(design/14) */
    public function validate(string $expression): void;  // 非法抛 ExpressionException(201)
}
```

实现形态:`Parser` 一次性产出不可变的 `CompiledExpression`(AST/步骤数组),`ExpressionEvaluator::evaluate` 在其上遍历求值;同一表达式在场景中会重复求值(断言 + 提取),解析结果可由内部 memoize。

## 5. 异常与错误码

```php
class ExpressionException extends \Ws\Http\Exception
{
    public readonly string $expression;   // 原始表达式
    public readonly int $position;        // 出错位置(语法错误时)
}
```

| code | 场景 | 消息示例 |
| --- | --- | --- |
| 201 | 语法错误 | `Invalid expression at pos 7: expected ']'` |
| 202 | (预留)调用方要求"空集即错"时显式抛 | `Expression matched 0 nodes: $.a.b` |
| 203 | 类型不匹配(仅比较操作符比较数值时抛,由 Comparison 触发) | `Cannot compare "abc" numerically` |

> 断言/提取场景**不会**遇到 202/203 走到抛出路径:断言层把空集转为断言失败(非异常);提取层按 on_missing 策略处理(design/15)。

## 6. 测试用例集(必须覆盖)

| 组 | 用例 |
| --- | --- |
| 文法 | §2 全部示例表达式解析通过;非法样本逐个断言 201(未闭合 `[`、裸 `*`、双 `..`、空 `[]`、`?(@>` 等残缺 filter) |
| member | 嵌套对象、数组上数字串 member、缺失键、unicode 键(如中文键 `$.数据.名称`) |

| wildcard | 对象通配、数组通配、通配后接下钻 |
| filter | ==/!=/>/>=/</<=/ =~、existence、字面量类型(数字/字符串/true/null)、filter 作用于对象 |
| 容忍性 | 深层残缺数据上任意路径 → 空集不抛 |
| 集成 | v1 example.json 中出现的全部 8 条路径(`list[0].xktvid`、`data.taocaninfo.course[0].starttime.time` 等)逐条验证 |

## 7. 与设计文档的接口约定

| 消费方 | 用法 |
| --- | --- |
| 断言器(design/12) | `source=json` 的 actual = `evaluate(response->body, path)->first()` |
| 变量提取器(design/15) | `match=json` 的提取值 = `evaluate(response->body, attr)`;按 multiple 取 all/first |
| 场景加载(design/14) | 脚本加载期对全部 asserts/setVar 路径跑 `validate()`,提前报错 |
