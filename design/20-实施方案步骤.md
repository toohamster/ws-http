## 2. 各步骤详细定义

### S1 工程基建

**动作**:重写 `composer.json`(name 保留 toohamster/ws-http;require: php ^7.4 + ext-curl + ext-json;require-dev: phpunit/phpunit ^9;autoload PSR-4 `Ws\Http\` → `src/Ws/Http`;bin 指向 bin/ws-http;minimum-stability: stable);`php74 composer.phar install`;写 `phpunit.xml.dist`(三个 testsuite,Integration 默认排除,`--group integration` 启用);建目录骨架与 `tests/bootstrap.php`(vendor autoload,无其他依赖)。

**测试用例**:`tests/Unit/SkeletonTest.php`——断言 autoload 生效(`new \Ws\Http\Exception()` 可实例化)。
**Done**:`php74 vendor/bin/phpunit --testsuite Unit` 绿。

### S2 core:异常 + Method + HeaderBag

**动作**:`Exception`(基类,错误码构造)、`RequestException`(curlErrno/curlError/url/method 只读属性,按设计 11 §7)、`Method` 常量接口(旧文件直接迁移 + `isBodyAllowed()`)、`HeaderBag`(设计 11 §2 全部方法:大小写不敏感、多值 add/get/all、fromRawHeaders 解析状态行/续行/多值、toCurlHeaders 小写输出)。

**测试用例**(`tests/Unit/Core/HeaderBagTest.php` 等):
- HeaderBag:get/has 大小写不敏感;add 同名三值 → all() 三值、get() 逗号拼接;remove/names/toArray;
- fromRawHeaders:多行头、状态行跳过、`\t` 续行并入、空值头(`Expect:`)保留空串、`Set-Cookie` 双值;
- toCurlHeaders:输出小写名、原始大小写丢失可接受;
- RequestException:属性与消息模板 `cURL error {errno}: {error} [{method} {url}]`。

**Done**:上述单测全绿;`php74 -l` 全部新文件通过。

### S3 RequestOptions

**动作**:按设计 11 §4 实现 wither 全集(timeout/timeoutMs/verifyPeer/verifyHost/caBundle/jsonOpts/defaultHeader(s)/cookie/cookieFile/auth/proxy/proxyAuth/curlOpt(s)/maxRedirects)+ 读取器;不可变性(withX 返回克隆);校验(timeout≤0 抛 InvalidArgumentException;verifyHost bool→0/2 映射)。

**测试用例**(`tests/Unit/Core/RequestOptionsTest.php`):

- 校验:timeout(0)/(-1) 抛异常;timeoutMs(500) 存储正确;
- auth/proxy/cookieFile 各字段读写;defaultHeader 合并与 withoutDefaultHeaders 清空;curlOpt 优先级叠加(两次 withCurlOpt 取后值)。

**Done**:单测全绿。

### S4 Response + Body

**动作**:`Response`(设计 11 §3:只读 code/statusLine/headers(HeaderBag)/rawBody/curlInfo/jsonError,body 仅当 Content-Type 含 application/json 且解析成功时填充,isOk()/header()/totalTime());`Body`(设计 11 §5:json/form/multipart/file/raw 返回 PreparedBody;json 失败抛 code 102;form 复用 Request::buildHttpQuery 拍平)。

**测试用例**(`tests/Unit/Core/ResponseTest.php` / `BodyTest.php`):

- Body:json 数组/对象编码与 Content-Type、json 编码失败异常、form 多维拍平、multipart files→CURLFile、raw 指定 Content-Type。

## 3. 执行纪律

1. **顺序执行**:S1→S11 严格按依赖;每步 Done 后才进入下一步;
2. **测试先行**:每步先落测试文件(以设计文档规格为断言依据),实现到绿;
3. **设计文档即契约**:实现与设计冲突时,停下来在会话中确认,不擅自偏离;若确认修改设计,同步更新 10–17 对应小节;
4. **记忆同步**:每步完成将关键经验(工具用法、踩坑)追加到 `.claude/memory/`;
5. **不推送远程**:所有提交仅本地;tag 打不推。
