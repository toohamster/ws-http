# 03 重构方案与实施步骤(PHP 7.4)

## 1. 目标与原则

- **目标**:以 PHP 7.4 重写 ws-http,保持对外能力与 API 形态,修复已知缺陷(见 01 文档 §6 B1–B11),补齐 Automated 引擎。
- **原则**:
  1. 行为兼容优先:现有公开方法签名不变;bug 修复项在 CHANGELOG 中明示为行为变更;
  2. 渐进迁移:核心(Request/Response/Body/Method/Watcher)先落地并通过测试,再动 Automated;
  3. 测试先行:每个模块迁移前先补 PHPUnit 用例(以旧实现行为 + 需求文档为基准);
  4. 不引入重依赖,保持零外部 require。

## 2. 目标架构与目录结构

```
ws-http/
├── composer.json               # php: ^7.4, ext-curl, ext-json; require-dev: phpunit ^9, phpstan, php-cs-fixer
├── src/
│   ├── bootstrap.php           # (可选) 兼容旧版的全局函数/别名加载,逐步移除
│   └── Ws/
│       ├── Http/
│       │   ├── Request.php             # cURL 引擎(配置 + send)
│       │   ├── RequestOptions.php      # (新)配置值对象:timeout/ssl/proxy/auth/cookie/headers/curlOpts
│       │   ├── ARequest.php            # 静态门面(修 B2)
│       │   ├── Response.php            # 响应对象(+isOk/header()/jsonError)
│       │   ├── HeaderBag.php           # (新)大小写不敏感头集合(修 B8)
│       │   ├── Body.php                # Request\Body 迁移 + json 自动 Content-Type(修 B6)
│       │   ├── Method.php              # 常量接口(原样保留)
│       │   ├── Exception.php           # 基类
│       │   ├── RequestException.php    # (新)cURL 传输层异常(含 errno)
│       │   └── Watcher.php             # 断言器(修 B1、B7;新增 assertBodyJsonPath)
│       │       └── Exception.php
│       └── Http/Automated/
│           ├── Bootstrap.php           # 执行器(修 B4;新增 run() + Report)
│           ├── Task.php
│           ├── Task/Body.php           # vars + requests + varReplace(递归)
│           ├── Task/Request.php        # 修 B3;dataMode/timeout/proxy/auth 解析
│           ├── StepResult.php          # (新)单请求执行记录
│           ├── Report.php              # (新)执行报告
│           ├── VarExtractor.php        # (新)setVar 实现(json path / header / raw_body)
│           ├── AssertResolver.php      # (新)asserts 实现(复用 Watcher 逻辑)
│           ├── CookieStore.php         # (新)跨请求 cookie
│           └── Exception.php
├── bin/
│   └── ws-http                   # CLI:php bin/ws-http run script.json [--report=json]
├── tests/
│   ├── bootstrap.php             # PHPUnit 引导(去掉 \Ws\Env 依赖)
│   ├── Unit/…                    # 纯单测(mock curl 或测试纯函数)
│   └── Integration/…             # 公网 httpbin 用例(CI 可 skip)
└── design/                       # 本设计文档
```

**关键设计决策**:

1. **Request 内部拆出 `RequestOptions` 值对象**:Request 只负责"配置收集 + 组装 curl + 执行",配置项集中在 Options 里,便于 `clone`、快照与测试(对应需求 A1-2/A1-3);
2. **`HeaderBag` 统一头处理**:请求头合并、响应头解析共用,大小写不敏感读写(一次解决 B8 与 Watcher 头断言的大小写问题);
3. **Automated 复用 Watcher**:asserts 的操作符实现在 Watcher\assertBodyJsonPath 中,Automated 只做映射,避免两套断言逻辑;
4. **异常分层**:`Exception`(基)← `RequestException`(传输层,含 errno)← 各模块异常;Watcher\Exception 独立保留(现签名);
5. **兼容策略**:`Request\Body` 命名空间原样保留(旧调用 `Ws\Http\Request\Body::json()` 不变);旧式 `output()` 调试调用删除(B5)。

## 3. 实施步骤(建议按阶段提交)

### 阶段 0:工程基建(0.5 天量级)

1. 更新 `composer.json`:`php ^7.4`、`ext-curl`、`ext-json`;require-dev 加 `phpunit/phpunit ^9`、`phpstan/phpstan`、`friendsofphp/php-cs-fixer`;`minimum-stability: stable`;
2. 搭 PHPUnit 骨架(`phpunit.xml`、`tests/bootstrap.php` 移除 `\Ws\Env` 依赖,自写轻量 output);
3. 清理:`.DS_Store` 加 gitignore;删除 `src/**/.DS_Store`;
4. 建立分支策略:`master` 保持旧版,`develop/php74` 承载重构。

### 阶段 1:核心 HTTP 客户端(需求 §1)

1. **测试先行**:为 `encodeUrl`、`buildHTTPCurlQuery`、`getFormattedHeaders`、`Response::parseHeaders`、JSON body 解析写单测(这些是纯逻辑,可直接测);
2. 新写 `HeaderBag`、`RequestOptions`,迁移 `Request`(保持方法签名;默认超时 30s;移除 B5 调试代码);
3. 迁移 `Response`(+`isOk()/header()/jsonError()`)、`Body`、`Method`;
4. 新增 `RequestException`,send() 错误路径携带 errno;
5. 修复 A2/A4 相关需求项;UA 更新为 `ws-http/2.0`;
6. 集成测试(httpbin.org):GET/POST/PUT/DELETE/PATCH、JSON/表单/multipart 文件上传、basic auth、重定向、cookie、超时。

**验收**:全部单测 + 集成测试通过;旧 README 用例逐条跑通(README 中"自动 Content-Type"差异按新行为更新)。

### 阶段 2:Watcher 断言(需求 §2)

1. 测试先行:现有断言语义逐条转 PHPUnit(含 IS_EMPTY/IS_VALID_JSON/regex/JSON 文件比对);
2. 迁移 `Watcher`,修复 B1(strpos 参数顺序)、B7(全局函数改为私有静态方法/工具类),`prettyPrintJson` → `JSON_PRETTY_PRINT`;
3. 新增 `assertBodyJsonPath`(点路径解析器 + 比较操作符 eq/ne/gt/lt/ge/le/not_null/contains),配套路径解析单测(`a.b[0].c`);
4. 头断言切换到 `HeaderBag`。

**验收**:断言全单测覆盖;手动 API 测试场景(README 中的 GitHub 示例)通过。

### 阶段 3:ARequest 门面(需求 §3)

1. 迁移 ARequest,修复 B2;补静态门面冒烟测试。

### 阶段 4:Automated 引擎补齐(需求 §4)

1. **解析层**:按 D-01/D-07/D-08/D-09/D-10 修 B3(条件反转)并补严格校验;`Task\Request::parse` 拆分为小的私有方法便于测试;data 为 file 类型时映射 CURLFile;
2. **执行层**:重写 `Bootstrap`——移除 break(B4),实现 Task type 1/2 失败策略(D-06)、StepResult/Report(D-11)、`varReplace` 支持数组/对象递归替换;
3. **后处理器**:`VarExtractor`(D-03,点路径取值复用阶段 2 的解析器)+ `AssertResolver`(D-04,映射到 Watcher);
4. **CookieStore**(D-12):先实现内存 jar(从响应 Set-Cookie 收集、按域名匹配回放),可选 cookieFile 持久化;
5. **CLI**:`bin/ws-http run script.json`,退出码 0=全部通过 / 1=存在失败;
6. 用 `example.json` 结构构造针对 httpbin 的场景脚本(登录式两步流程:请求 1 提取变量 → 请求 2 使用),作为引擎集成测试。

**验收**:示例场景脚本端到端跑通;断言失败、变量提取失败、连接失败三类错误场景下的报告与退出码正确。

### 阶段 5:收尾

1. PHPStan(≥level 6)与 PHP-CS-Fixer 全量通过;
2. 重写 README(三大用法 + 迁移差异说明:UA 2.0、默认超时 30s、CA 使用系统证书、`assertBody` bug 修复后的行为变化);
3. 打 tag(`2.0.0-alpha` → `2.0.0`),删除废弃文件(`_ssl/ca-bundle.crt`、旧 tests);
4. CHANGELOG.md 记录行为变更清单(B1/B2/B3/B4/B5/B6/B8 及默认值变化)。

## 4. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 现有调用方依赖 bug 行为(如 B1 assertBody) | CHANGELOG 显式声明;major 版本号 2.0 |
| 旧实现无可注入点,cURL 层难以 mock | 纯逻辑(编码/解析/断言)抽成可测函数;集成测试用公网服务 + CI skip 标记 |
| Automated JSON 无正式 schema | 以 example.json + 需求文档 §D1 为契约,解析层做严格校验并给可读错误 |
| 内置 CA 证书过期导致 SSL 失败 | 默认切系统 CA;保留 `verifyFile()` 供显式指定 |
| `minimum-stability: dev` 历史包袱 | 收紧为 stable,依赖面本来就空,风险低 |
