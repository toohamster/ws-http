# 15 变量系统细化设计(functional:变量作用域 / 占位符替换 / 提取器)

> 层归属:**functional**。使用者:场景脚本作者(通过脚本字段间接使用)。

**简单路径**(脚本视角):

```jsonc
"variables": [ { "name": "city", "value": "440100" } ],
"extract":   [ { "var": "token", "source": "json", "path": "$.token" } ]
// 请求中任意字段写 ${city} / ${token} 即可
```

**简单路径使用者只需要**:`variables` 声明、`${name}` 引用、`extract` 三条。onMissing 策略、类型保留语义、转义规则是深水区,见 §3/§4。

> 范围:`VariableScope`(变量存储)、`ScenarioResolver`(${var} 深替换)、`VarExtractor`(响应提取)。是自动化引擎的"血液系统"。
> 旧代码参考:`Automated/Task/Body.php` 的 `varReplace()`;v1 缺陷:只替换字符串、无法提取(postProcessors 未实现)、`$var` 与 `${var}` 双占位符并存。

## 1. 总览:变量的完整生命周期

```
① 声明     ② 消费            ③ 产出              ④ 消费            ⑤ 报告
variables → ${var} 替换 → 步骤执行 → extract 提取 → 后续步骤 ${var} → Report.variables
(初始值)   (请求前)         (Response)  (回写 Scope)    (请求前)         (终值快照)
```

## 2. VariableScope(变量存储)

```php
final class VariableScope
{
    /** @param Variable[] $variables  场景声明 + 运行中追加 */
    public function __construct(array $variables = []);

    public function get(string $name): VarValue;         // 未声明 → VarValue(undefined)
    public function set(string $name, mixed $value): void;  // 已声明 → 更新;未声明 → 自动追加(提取器回写场景)
    public function has(string $name): bool;
    public function names(): array;
    public function snapshot(): array;                   // [name => 当前值] 报告用
    public function secrets(): array;                    // secret=true 的变量名列表(design/16 §3.3 脱敏用)
}
```

### 2.1 变量命名规则

```
/^[A-Za-z_][A-Za-z0-9_]*$/    ; 即 PHP 变量名规则去掉 $ 前缀
大小写敏感;加载期校验(code:402,design/14 V8)
```

### 2.1.1 secret 标记(S8 补充,随 S9 Report 消费)

变量声明可带 `"secret": true`(Schema v2 顶层 variables 及运行期 `set()` 的第四参):

- **语义**:该变量的值属于敏感数据(密码/token/签名),Report/StepResult 输出 `variables` 快照时值替换为 `***`(design/16 §3.3);
- **传导**:运行期 extract 提取**覆盖** secret 变量(如重新登录换 token)时,secret 标记保持(按变量名绑定,不按值绑定);
- **边界**:secret 只影响**输出层**(报告/CLI);变量在引擎内部(resolve/extract)始终使用真实值——脱敏不改变执行语义。

### 2.2 VarValue(变量值包装)

```php
final class VarValue
{
    public readonly bool $defined;    // 是否有值
    public readonly mixed $value;     // string|int|float|bool|null|array
}
```

区分「未定义」与「值为空串/null」——v1 中 `empty($val)` 把三者混为一谈是行为缺陷。

## 3. extract:变量提取规则(VarRule)

Schema v2 中每个 HTTP 步骤的 `extract` 数组元素。**source 为契约化注册表**(实现 `Contract\ExtractorInterface`):functional 内建 json/header/raw_body/status/time/template 六种默认 source;plugin 可注册新 source(如从 XML 提取)。内建规则如下:

```jsonc
{ "var": "token", "source": "json", "path": "$.list[0].xktvid",
  "multiple": false, "onMissing": "fail" }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `var` | 是 | 目标变量名(规则 §2.1) |
| `source` | 是 | `json` \| `header` \| `raw_body` \| `status` \| `time` \| `template` |
| `path` | source=json 必填 | JSONPath(design/13);source=header 时为**头名**;source=template 时为**模式串**(见 §3.1);其余忽略 |
| `multiple` | 否,默认 false | true 时取 `all()` 结果数组回写;false 取 `first()` |
| `onMissing` | 否,默认 `fail` | 提取无匹配时:`fail`(步骤失败,failFast 下终止)/ `skip`(保持变量不变)/ `default` + `defaultValue` 字段 |

### 3.1 各 source 的提取语义

| source | 匹配值来源 | 多值行为(multiple=true) |
| --- | --- | --- |
| `json` | `ExpressionEvaluator::evaluate(response->body, path)` | all() 节点数组 |
| `header` | `response->header(path)`(大小写不敏感);多值头返回逗号拼接串 | `all(name)` 值数组 |
| `raw_body` | `response->rawBody` 整串 | 无意义,忽略 multiple |
| `status` | `response->code`(int) | — |
| `time` | `response->totalTime()`(float) | — |
| `template` | 见下 | — |

**source=template({name} 模板提取)**:对**字符串**做命名占位符提取,由 core `StrKit::extract()` 实现(`{name}` 占位符 → 命名捕获组,声明式替代裸正则)。

```jsonc
// 提取目标:rawBody 中的 csrf token(v1 ATest.php 中 preg_match csrf-token 场景的声明式写法)
{ "var": "csrf", "source": "template",
  "path": "<meta name=\"csrf-token\" content=\"{token}\" />" }
// 产物:变量 csrf = 整个关联数组 {"token": "..."};取单字段时配合后续 json 不可用——
// 简化约定:默认取第一个命名字段的值写入变量;套件需要全部字段时 multiple=true
```

- **输入**:source=template 时输入恒为 `rawBody`(从 header 提取请先用 header source);`path` 字段承载**模式串**;
- **产物**:默认 `multiple=false` 时取**首个**命名字段的值(标量)写入 var;`multiple=true` 时整个关联数组写入 var;
- **边界**:模式中无任何 `{name}` 占位符 → 配置错误(加载期校验,V11);匹配失败 → 按 onMissing 策略;
- **多占位符模糊性**:相邻占位符间无字面量锚点时匹配结果是贪婪/非贪婪实现的实现细节,文档提示"占位符间应有字面量分隔",不做强校验。

### 3.2 提取失败(无匹配)的处理路径

```
无匹配(onMissing 决定)
 ├─ fail     → 步骤标记 failed(消息:extract var "{var}" matched nothing: {path}),按 failFast 终止
 ├─ skip     → 记录 warning 到 StepResult.warnings,变量保持原值
 └─ default  → 变量写入 defaultValue(缺省 "" )
```

> 修复 v1 缺陷:v1 完全未实现提取;且 v1 JSON 中 `"var": "bookingKtvId"` 的期望值匹配 `attr: "bookingKtvId"`(无路径能力),v2 全部走 JSONPath。

## 4. ScenarioResolver:${var} 深替换

### 4.1 占位符语法(统一,废弃双语法)

```
${varname}          ; 唯一形态
转义:$${literal}    ; $$ 前缀 → 输出 ${literal} 字面量(不做替换)
未定义变量 → 见 §4.3
```

### 4.2 替换算法(深替换)

对步骤对象树的递归替换,输入为 HttpStep 的可替换面(url/headers 值/auth 各字段/proxy 各字段/body.content/timeout 字符串):

```
resolve(value):
  string  → replaceInString(value)
  array   → map(resolve)          # 保序,键不变
  object  → map(resolve)          # 属性逐个替换
  其他标量 → 原样

replaceInString(s):
  扫描 ${name} 占位符(整串或局部):
    - 整串完全匹配且变量值为数组/对象 → 直接返回该复合值(类型保留,不字符串化)
      例:body.content 为 params 模式时 value: "${listVar}" 可展开为数组
    - 整串完全匹配且变量值为标量 → 返回标量原类型(数字保持 int,不字符串化)
    - 局部嵌入(串内混合文本)→ 值字符串化后拼接;复合值 → JSON 编码后拼接
    - 未定义 → 按 §4.3
  $${...} → 剥离一个 $,原样输出
```

**类型保留语义**(v1 全部字符串化的改进):`${port}` 若变量值为 int 1080,替换进 proxy.port 时保持 int;仅字符串上下文中嵌入时才 `strval`。

### 4.3 未定义变量的处理

| 发生位置 | 策略 |
| --- | --- |
| 步骤请求面(url/headers/body/auth/proxy) | 步骤直接 failed:`Undefined variable "{name}" in step "{stepId}"`;failFast 下终止。**不做静默空串替换**(v1 缺陷:把未定义静默替换为 "") |
| 断言 expected 字段 | 同上(断言构造期失败) |

> 权衡说明:引擎不做"惰性引用"(如 `${{var}}` 二次解析),避免 v1 那种隐式传递;若需要引用前一步响应,必须显式 extract。

## 5. VariableScope 与引擎各层的交互(契约)

| 层 | 调用 | 时机 |
| --- | --- | --- |
| Runner(design/16) | `scope.snapshot()` | 场景结束时写入 Report.variables |
| Runner | resolve 顺序:① 场景级 variables 写入 scope → ② 每步执行前 deep-resolve 步骤对象树 → ③ 步骤 extract 回写 | 每步 |
| VarExtractor | `scope->set(var, value)` | 提取成功后立即回写(同步骤内后续 extract 可引用刚提取的值——按 extract 数组顺序执行) |
| AssertionRunner | expected 中的 `${var}` 已在 resolve 阶段替换完毕 | 断言执行时无需感知变量 |

> 与 v1 差异:v1 的 varReplace 在 doRequest 内逐字段调用、且 `$token`/`${token}` 双语法随机出现;v2 收敛为执行前的一次性深替换。

## 6. VarExtractor API 规格

```php
final class VarExtractor
{
    public function __construct(
        private ExpressionEvaluator $evaluator,
    );

    /** @param VarRule[] $rules  按序执行,前序结果对后序可见 */
    public function extract(Response $response, array $rules, VariableScope $scope): ExtractionResult;
}

final class ExtractionResult
{
    /** @return VarWrite[] 成功写入(变量名, 值) */
    public array $written;
    /** @return VarWarning[] skip/default 事件(onMissing 处理) */
    public array $warnings;
    /** @return ExtractFailure[] fail 事件 */
    public array $failures;
}
```

- `written`/`warnings`/`failures` 全部进入 `StepResult`(design/16 §3),报告可见;
- **不抛异常**(引擎内部收集语义,与 AssertionRunner 一致)。
