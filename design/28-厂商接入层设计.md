# 28 厂商接入层设计(ChatTransport 抽象 + 完整重试 + 错误语义分类)

> 层归属:组件段新子命名空间 `Ws\Http\NanoGpt\Transport\`;依赖单向:Transport → Plugin\OpenAI/core,NanoGpt 编排层只依赖 Transport 接口,不感知任何厂商。
> 背景:多厂商接入是使用者必然面对的现实(DeepSeek/千问/Claude/千帆…);`3rd/php-ai-sdk-main/`(PHP 8 + Guzzle 多厂商库,参考物不入库)作对照。日期:2026-10-09。
> **本设计是对 design/21 §1 原初承诺的兑现,不是外挂补丁**:21 自我定义为"可复用编排层",但其 Agent 直接依赖 `Plugin\OpenAI\Client` 具体类——被单点绑死在 OpenAI 协议上,使用者接协议级厂商(如 Claude)即绕开整个组件,全部编排价值归零。本设计解此绑。

## 1. 架构定位:编排与传输分离(design/21 §1 修订)

**剖开一次 agent 对话,按协议无关/协议相关切一刀**:

```
┌─────────────── 协议无关(NanoGpt 编排,永久资产)───────────────┐
│ Agent loop 状态机 │ 工具协议/注册表 │ 沙箱 │ Conversation/快照/压缩 │ 预算 │
└────────────────────────────┬─────────────────────────────────┘
                      ← ChatTransportInterface(翻译边界)→
┌─────────────── 协议相关(每厂商一份,可替换)────────────────────┐
│ 认证方式 │ 端点与请求体形状 │ 响应结构→统一结果 │ 错误语义→分类 │ 能力档案 │
└───────────────────────────────────────────────────────────────┘
```

**切口的判据(验收标准)**:编排层源码里出现任何厂商名(`if openai/claude/deepseek…`)即失败。翻译责任完整落在厂商实现——Claude 类厂商的 messages 拆分/tool 块结构/stop_reason 语义由其 Transport 独自消化,编排层零感知。

design/21 修订条目:

- §1"是"第 1 条:"建立在 OpenAI 协议上" → "**编排与协议分离**:loop/工具/沙箱/会话是协议无关资产,传输经 ChatTransportInterface 可替换";
- §1"不是"第 1 条"不是第二个 OpenAI 客户端"保留并强化:编排层连 OpenAI 兼容传输都不实现,只定义边界;
- 简单路径示例更新:`new Agent(new OpenAiCompatibleTransport([...]), 'model')`——多厂商时代使用者的第一行代码。

## 2. ChatTransportInterface(传输契约,组件层唯一接口)

```php
namespace Ws\Http\NanoGpt\Transport;

use Ws\Http\NanoGpt\ChatResult;
use Ws\Http\NanoGpt\ModelInfo;

interface ChatTransportInterface
{
    /**
     * 一轮对话。
     * @param array<int, array<string, mixed>> $messages OpenAI wire 格式(编排层通用语;
     *        协议级厂商由实现独自翻译,如 Claude 的 system 拆分/tool_use 块)
     * @param array<string, mixed> $options 采样参数(max_tokens/temperature)+ retry 策略(§3)
     * @throws AgentException 携带语义分类 code(§4)
     */
    public function chat(array $messages, array $options = []): ChatResult;

    /**
     * 能力档案:模型目录 + 静态能力声明。
     * ModelSourceInterface(§8.1/§8.2 时代产物)语义并入此处——对话域的抽象收口,不再分裂。
     * @return array{models: array<int, ModelInfo>, contextWindow: ?int, maxOutputTokens: ?int}
     */
    public function capabilities(): array;
}
```

- **只此一个接口**——无 Manager/工厂/注册表(组装是壳/使用者的事);Agent 构造收此接口,依赖倒置完成;
- **capabilities 并入 ModelSource 语义**:§8.2 壳层 ModelProvider 适配器保留目录与 /init 分派,但 OrcaRouterAdapter/GenericAdapter 薄壳化(内部持有 Transport,capabilities 委托)——"服务身份 → Transport 配置"归壳,"模型目录解析"归 Transport;
- messages 用 wire 格式作编排层通用语:Conversation/snapshot/回填已是 wire 格式,翻译成本不传染编排层。

## 3. 重试(完整语义,首版交付;参考 3rd/php-ai-sdk HttpClientFactory)

**不是策略位预留——完整实现**(429 在 N4 冒烟真实发生过;参考实现在手;php74 语法无障碍):

```
options['retry'] = [
    'max'         => int,     // 最大重试次数,默认 0 = 不重试
    'delay_ms'    => int,     // 首次退避,默认 1000
    'multiplier'  => float,   // 退避乘数,默认 2.0(指数:delay_ms * multiplier^attempt)
    'on_status'   => int[],   // 触发重试的状态码,默认 [429, 500, 502, 503, 504]
];
// Retry-After 响应头存在 → 其秒数优先于退避计算
// 重试耗尽 → 最后一次错误进入 §4 错误映射
```

## 4. 错误语义分类(映射,不建新异常体系)

Transport 实现把 HTTP 层失败翻译为**语义分类 code**(AgentException 600 段内扩充传输子码),Agent 现有 try/catch 透传到 error 事件(加 category 语义,异常结构不变):

| code | 分类 | 触发 |
| --- | --- | --- |
| 620 | auth | 401/403 |
| 621 | rate-limit | 429(重试耗尽后) |
| 622 | server | 5xx(重试耗尽后) |
| 623 | timeout | 连接/执行超时 |
| 624 | unexpected-response | 2xx 但结构不可解析 |

编排层不 import 厂商名,但可对分类分支(如 rate-limit 提示 /compact 或等待)。

## 5. 实现与装配(协议族 Transport + 配置实例,薄起家)

**Transport 的分类轴是协议族,不是厂商**(评审定调):厂商之间只差 baseUrl/模型名/鉴权配置时,它们是**同一 Transport 的不同配置实例**(零代码);只有协议形状本身不同(认证方式/端点/消息结构整套变化)才需要新的 Transport 类。

```
ChatTransportInterface(契约)
  ↑
OpenAiCompatibleTransport          ← OpenAI 协议族实现
  · 配置实例:DeepSeek/千问/Kimi/Moonshot/MiniMax/orcarouter… = 换 config,零代码
  · 子类仅在配置表达不了的差异出现时才写(如某家响应特殊字段)
ClaudeTransport(将来)             ← 另一协议族;其下 Claude 官方/Bedrock = 配置实例
```

```
NanoGpt\Transport\
├── ChatTransportInterface.php
└── OpenAiCompatibleTransport.php   # 首个实现(真实消费者:cc-gpt 壳)
      ├── 构造收 array $config:api_key/base_url/model/timeout/retry(DEFAULT 常量兜底,构造期归一)
      ├── chat():委托 Plugin\OpenAI\Client 发请求 → ChatResult 解析 → 重试循环包裹(§3)
      ├── 错误映射(§4)
      └── capabilities():经 /models → ModelInfo[]
```

既有物归位:

| 既有物 | 处置 |
| --- | --- |
| Plugin\OpenAI\Client | **不动**(人的业务对接面,design/17 定位);Transport 是程序消费侧伴生,委托不重复 |
| ModelProvider 适配器(壳,§8.2) | 保留目录/+init 分派;薄壳化(capabilities 委托 Transport;"服务身份 → Transport 配置"归壳) |
| ModelSourceInterface(组件) | 废弃并入 capabilities() |
| VendorCatalog(V1,已提交) | **回退删除**(配置实例 + 类即档案;静态清单否决) |
| ChatResult(V2 未提交) | **重新实现**(D1 一并;传输契约的统一返回类型,解析收口 + reasoning_content 兼容) |
