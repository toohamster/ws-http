# 27 场景输出契约(场景作为取数函数:outputs 声明 + 结果集提取)

> 层归属:**functional(Automated)**——场景 Schema 加一个字段 + 一个校验 + 一个取值辅助;消费端跨层(Agent 工具/编程调用/CLI)。
> 背景(评审 2026-09-21):"提取"有一类**专属形态**——场景脚本作为**取数函数**用:定义变量 → 执行场景(内部请求/提取/断言,过程任意复杂)→ 从运行结果中提取**预先声明的输出变量**作为返回(JSON 结果集)。场景引擎(design/14–16)支持了一半:变量/提取/断言/Report 完整,`Report::variables()` 终值快照已有;**缺"输出变量清单"的声明位与取值出口**。
> 与 design/25 C5 的关系:ApiFetchTool 首版是"单请求 + extract 槽"(单请求取数);本设计落地后它**升级为可接受场景脚本参数**——场景取数(多步流程的最终产物)是其超集,演进无返工。

**简单路径**(场景作者视角,三行新增):

```jsonc
{
  "id": "get-weather",
  "name": "取天气",
  "outputs": ["city", "temp"],                    // ← 唯一新字段:输出变量白名单(结果集签名)
  "variables": [{ "name": "cityCode", "value": "440100" }],
  "steps": [
    { "type": "http", "id": "s1", "name": "查天气",
      "url": "https://api.example.com/weather?code=${cityCode}", "method": "GET",
      "extract": [ { "var": "city", "source": "json", "path": "$.city" },
                   { "var": "temp", "source": "json", "path": "$.data.temp" } ] }
  ]
}
```

```php
// 编程调用(取数函数形态):
$result = (new ScenarioOutput())->extract($report, $scenario->outputs);
// → {"city": "广州", "temp": "26℃"}(只含声明的变量;缺 = onMissing 语义决定)
```

> 简单路径使用者只需要:场景里写 `outputs`,跑完拿结果集。契约细节见 §2–§3。

## 1. 概念与边界

**场景作为取数函数 = 场景(过程)+ outputs(返回值签名)+ 结果集(出口)**:

| 环节 | 归属 | 现状 |
| --- | --- | --- |
| 过程(请求/提取/断言) | 场景引擎(design/14–16) | ✅ 已有,零改动 |
| 输出声明 | **本设计**:顶层 `outputs` 数组 | 新增字段 |
| 结果集出口 | **本设计**:ScenarioOutput::extract(纯函数) | 新增薄辅助 |
| 失败语义 | 既有:Report.isSuccess + failed 步骤追溯 | 复用 |
| 缺值语义 | 既有:onMissing(fail→脚本失败/skip→保持/default) | **复用,不新造** |

**不是**(防过度设计):

- **不做"输出变换/二次加工"**(如模板渲染/字段重命名)——结果集就是变量的原值;要变换属消费端职责;
- **不做调用侧覆盖 outputs 的复杂合并语义**——调用方可收窄(子集),不扩充(防场景签名失真);
- **不做多结果集/分页聚合**——一个场景一次运行一个结果集;批量迭代是 design/23 Dataset 的事(正交);
- 不动 secret 脱敏——outputs 含 secret 变量时,结果集**同样经 Redactor**(现有 Redactor::apply 复用,防密钥经取数口外泄)。

## 2. Schema 契约(design/14 修订)

```jsonc
"outputs": ["city", "temp"]     // 可选;字符串数组,场景内唯一
```

校验规则(追加 design/14 V 序列):

- **V19**:`outputs` 必须是字符串数组,元素唯一、符合变量命名规则;每个名字必须**可产出**——出现在 `variables` 声明**或任一步骤的 extract[].var / pause[].var** 中(防拼错静默返回空);违例 402(JSON Pointer 指到具体元素);
- outputs 与 `settings.iterate`(design/23)正交可组合:Dataset 每轮的子 Report 各自出结果集(batch 场景 = 结果集列表)。

## 3. 出口契约(ScenarioOutput)

```php
namespace Ws\Http\Automated;

/**
 * 场景输出取值(design/27 §3):场景作为取数函数的出口——纯函数,无执行职责。
 */
final class ScenarioOutput
{
    /**
     * 从运行结果提取声明的输出变量。
     *
     * @param string[] $outputs 场景 outputs(空数组 = 返回 {},调用方应先判场景是否声明)
     * @return array<string, mixed> 结果集(键序 = outputs 声明序;值 = 变量终值;secret 经 Redactor)
     * @throws AutomatedException 630 场景未声明 outputs(调用方误用,编程期暴露)
     */
    public function extract(Report $report, array $outputs): array;
    // 实现:array_intersect_key(report->variables(), flip(outputs)) + Redactor::apply(复用)
    // 顺序保持:按 outputs 声明序输出(结果集的稳定性,消费端/测试可依赖)
}
```

- **不校验 Report 成败**——调用方先判 `isSuccess()`(失败时的"取数"语义 = 调用方决策:重试/报错/取部分值;引擎不替消费端定策略);
- CLI 可选增强:`--output=vars`(打印结果集 JSON)——首版**不做**(编程入口已够,CLI 等真实诉求);
- secret 语义:outputs 可声明 secret 变量(如取 token 供后续流程),**结果集内同样脱敏**——要真值须以编程方式读 scope(与 Report 契约一致,防止取数口成为脱敏旁路)。

**风险与对策**:① outputs 声明了但提取失败(onMissing=fail)→ 脚本已 failed,结果集取不到该键——文档明示"结果集完整性以脚本成功为前提";② outputs 与 future 字段演进冲突 → V19 的"可产出"校验是防御性约束,新来源(extract 新 source)自动满足;③ 场景被当取数函数滥用(重逻辑塞 outputs 场景)→ 这是特性不是风险——场景复用正是目的,文档给出"过程复杂度无上限,签名只看 outputs"的定位语。
