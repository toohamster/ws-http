# 24 会话与记忆设计(Conversation 演进 + 会话历史管理 + 显式长期记忆)

> 层归属:**组件段(`Ws\Http\NanoGpt\`)与壳段(`CcGpt\`)各自落位**,依赖单向:壳 → 组件。
> 背景:design/21 §7.1 评审记录(短期/长期记忆拆分、不做自动提炼)是本设计的底稿;§6 Conversation 预留了"session.json 扩展"。
> 范围演进(需求评审 2026-09-20):用户提出 `/context` `/compact` `/rewind` `/clear` 命令族——本质是**会话历史管理**,与"记忆"共用同一底座:Conversation 只有"追加"语义,缺"截断/替换/快照/持久化"语义。设计重心在底座,命令是壳的一层皮。

**简单路径**(壳命令视角,使用者无感知底座):

```
you> 帮我分析 cc-gpt/.work/data.json
⚙ read_file {"path":"data.json"}
  ↳ ...文件内容...
(上下文接近模型窗口上限时,壳自动提示并压缩)
[auto-compact] 上下文已压缩:8 → 2 条消息(估算 92k → 12k tokens)
you> 继续分析第二部分
...
you> /rewind            # 回到之前某轮
  1) 帮我分析 cc-gpt/.work/data.json
  2) 继续分析第二部分
  rewind to [1]: 1
(会话截断至第 1 轮 user 消息前)
```

> 简单路径使用者只需要:命令存在、按提示选序号。底座(分段/压缩/预算估算)见 §2–§4。

## 1. 概念与边界

**两个正交的问题(继承 design/21 §7.1 评审,勿反复)**:

| | 会话历史管理(本设计主体) | 显式长期记忆(§6) |
| --- | --- | --- |
| 是什么 | 当前对话的 messages 生命周期管理(查看/压缩/回退/清空/持久化) | 用户显式要求保留的事实条目 |
| 形态 | messages[](wire 格式)+ session 文件(.runtime,过期即弃) | memory 条目(.work,同产出物生命周期) |
| 消费 | 原样/压缩后回放进请求体 | system prompt 附加段 |
| 命令 | /context /compact /rewind /clear /resume | /memory remember/forget/list |

**不是**(防过度设计):

- 压缩摘要**不写进长期记忆**——一次性生成物,严格分离;
- **不做多版本历史**(rewind/compact 后落盘"当前态",历史不额外保留快照树)——git 语义超出 CLI 工具定位;
- **不做精确 token 计数**——不引 tiktoken(零依赖约束),估算用保守上界,文档明示;
- **不做自动提炼记忆**(design/21 §7.1 决策不变);
- 压缩**不改变 Agent loop**——Agent 只消费 messages,压缩发生在两次 run 之间。

## 2. 组件层:Conversation 演进(向后兼容,新增不改动)

```php
final class Conversation
{
    // 已有:append / messages / usage / accumulateUsage / reset / forRequest / system

    /** system 运行期可变点(Memory::systemPromptBlock 注入后即时生效,无需重建 Agent);
     *  同 durationMs 的"包内可变点"先例(@internal 语义,对外仅壳/组装层调用) */
    public function setSystem(?array $system): void;

    /** rewind 底座:截断 index 及其后(新 messages 序列 = [0..index) ) */
    public function truncateFrom(int $messageIndex): void;

    /** 持久化底座:完整状态(v 版本字段 + messages + usage + system) */
    public function snapshot(): array;

    /** @param array<string, mixed> $snapshot 未知版本抛 611(session 格式不兼容) */
    public static function restore(array $snapshot): self;

    /** 检查点列表:role=user 消息的 (index, isSummary, 前缀文本) —— /rewind 展示与截断点选择 */
    public function userCheckpoints(int $prefixWidth = 40): array;
}
```

约束:

- `truncateFrom` 的 index 必须落在 **user 边界**(checkpoint 的 index)——工具调用对(tool_calls + role=tool 消息)不可拆,否则下一次请求违反 OpenAI 协议(605);
- **rewind 只动 messages,不动 usage**(usage 是跨轮累计口径,测试钉住);
- **rewind × compact 交互语义(评审补充)**:压缩后 messages 里的摘要消息是一条 role=user 消息,`userCheckpoints` 对它标记 `isSummary: true`(/rewind 列表显示"[摘要] 历史压缩点",**可选为截断点**——截到摘要之前 = 丢弃摘要回到"空白+更早轮"状态);**压缩前被替换掉的历史不可恢复**(多版本不做,§1 边界),/rewind 展示文案明示这一点;
- snapshot 版本:字段 `v: 1`;`restore()` 遇未知版本抛 611(引导 /clear 重建)。

## 3. 组件层:会话持久化(短期记忆)

```php
namespace Ws\Http\NanoGpt;

interface ConversationStoreInterface
{
    /** @return string[] 已有 session id 列表(新→旧) */
    public function list(): array;

    /** @return array<string, mixed>|null snapshot */
    public function load(string $sessionId): ?array;

    /** @param array<string, mixed> $snapshot */
    public function save(string $sessionId, array $snapshot): void;

    public function delete(string $sessionId): void;
}

final class FileConversationStore implements ConversationStoreInterface
{
    /** @param string $dir 落 .runtime/sessions(design/21 §8 三区:草稿区,过期即弃) */
    public function __construct(string $dir);
    // 文件:<dir>/<sessionId>.json(内容 = Conversation::snapshot + savedAt);
    // sessionId 默认 date('Ymd-His'),/resume 显式选择
}
```

- 壳默认行为:REPL 正常退出(/quit / EOF)自动 save 当前会话;/clear 同时 delete session;
- **currentSessionId 归属(评审补充)**:壳(Application/Context)持有 currentSessionId——新起 REPL 时生成(date('Ymd-His'));/resume 切换到目标 id(恢复其 snapshot;当前未保存先提示);/clear 只删当前 id 并生成新 id。Conversation 本身不感知 session id(它只是状态,身份是壳的);
- Agent 零感知:壳在 run 间隙调用 store,不动 Agent/Conversation 内部时序。

## 4. 组件层:上下文预算与压缩器

### 4.1 ContextBudget(预算判定)

```php
final class ContextBudget
{
    /**
     * @param int $contextWindow 模型上下文窗口(如 128000;壳配置注入)
     * @param int $reserveForOutput 预留输出空间(默认 4096)
     */
    public function __construct(int $contextWindow, int $reserveForOutput = 4096);

    /** 保守上界估算:统一公式 ceil(UTF-8 字节数 / 3)(中文 ≈1 token/字偏保守,ASCII ≈4 字节/token 偏保守;
     *  零依赖、实现 5 行,不精确但方向正确——只会高估不会低估) */
    public function estimateTokens(array $messages): int;

    /** 估算 ≥ 预算 80% → true(预算 = contextWindow - reserveForOutput) */
    public function needsCompact(array $messages): bool;

    /** 占用比(0–1,/context 展示) */
    public function usageRatio(array $messages): float;
}
```

### 4.2 Compactor(压缩策略契约 + 内建 LLM 实现)

```php
interface CompactorInterface
{
    /**
     * 把 messages[start..end] 压缩为一条摘要消息。
     * @param array<int, array<string, mixed>> $messages 待压缩段(整段,含 role=tool)
     * @return array<string, mixed> wire 格式摘要消息:
     *   ['role' => 'user', 'content' => "【历史摘要】..."] —— 作为普通 user 消息回放
     */
    public function compact(array $messages): array;
}

final class LlmCompactor implements CompactorInterface
{
    /** 注入 ChatEndpoint 的宿主 client + 摘要上限;压缩是一次 LLM 调用(诚实暴露,非本地函数) */
    public function __construct(\Ws\Http\Plugin\OpenAI\Client $client, string $model, int $summaryMaxTokens = 1024);
    // prompt 模板:要求保留"任务目标/关键结论/未完成事项/重要数值",输出纯文本
}
```

- 压缩**保留消息分段语义**:调用方保证 start/end 落在 user 边界;Compactor 不做边界判定(单一职责);
- **压缩请求自身的防超限(评审补充)**:待压缩段里的 role=tool 消息(工具结果可能巨大)在进入摘要 prompt 前**截断到每条 2000 字符**——否则"上下文超限→触发压缩→压缩请求本身超限"死锁;截断只影响摘要输入质量,不影响原 messages;
- **压缩是阻塞操作(硬规则,评审确认 2026-09-21)**:压缩执行期间壳不接受/不处理任何新输入(同步 REPL 天然保证:压缩发生在两次 readLine 之间);压缩进行中用户敲入的内容在**压缩完成后**才被读取处理(终端缓冲,不丢失);压缩失败(612)时缓冲中的输入继续按原会话处理。UI 行为契约:
  - 压缩开始 → 提示 `compacting…`(附被压缩段消息数);
  - 压缩完成 → 显示结果(如 `8 → 2 messages (est. 92k → 12k tokens)`);
  - 期间**无提示符**——提示符的出现即"压缩已结束、可以输入"的信号;没有提示符 = 引擎忙。
  - 同模式适用于 /model 切换对账(§6.1)等一切阻塞式会话操作;
- 失败路径:LLM 调用失败 → AgentException 612,壳提示"压缩失败,可重试或 /rewind"——原 messages 不动(压缩是"先算后换",非原地)。

## 6. 显式长期记忆(§7.1 底稿落地)

```php
final class Memory
{
    /** @param string $file 落 .work/memory.json(用户明确要求保留,同产出物生命周期) */
    public function __construct(string $file, int $maxEntries = 100);

    /** 追加条目(带时间戳);超上限时丢弃最旧并写入警告(壳提示) */
    public function remember(string $text, array $tags = []): void;

    /** @return array<int, array{text: string, tags: string[], at: int}> */
    public function recall(?string $tag = null): array;

    public function forget(int $index): void;

    /** system prompt 附加段(条目超上限截断最旧);无条目返回 null */
    public function systemPromptBlock(): ?string;
}
```

- 只做**用户显式写**(/memory remember);模型经工具自主写列预留(风险:错记污染);
- 消费方式:Conversation::setSystem(§2 新增)运行期注入——/memory remember 后**下一轮即生效**,无需重建 Agent(此为 setSystem 存在的动机);

## 6.1 模型能力档案与切换对账(评审补充:窗口是模型属性,不是全局配置)

**动机**:原设计把 contextWindow 当 settings 全局值是错的——每个模型的上下文参数(窗口/最大输出)不同,且 /model 切换时**当前上下文数据**(已有 messages)必须对新窗口重新对账。

**契约扩展**(design/21 §8.1 联动小改):ModelSourceInterface 返回结构加可选能力字段:

```php
// @return array<int, array{id: string, name: string, pricing: string, contextWindow?: int, maxOutputTokens?: int}>
public function models(): array;
// 三渠道统一收进 ModelSource 抽象:
//   OrcaRouterModelSource:网关响应扩展字段读取(有则填)
//   StaticModelSource:手写档案(百炼类场景)
//   都拿不到 → null,/model <id> 时壳提示手动输入窗口
```

**/model 切换对账流程**(选择 id 后执行):

```
1. 从 ModelSource 取 {contextWindow, maxOutputTokens} → 写入 settings(model + 能力档案)
2. ContextBudget 重建(窗口 = 新模型档案;不再读全局 settings.contextWindow)
3. 对账:estimateTokens(当前 messages) vs 新窗口
   a) 未超限        → "switched to X (window 128k, context usage ~12%)"
   b) ≤ 新窗口 80%  → 警告 "usage ~95% of new window, consider /compact"(不强制)
   c) > 80%         → 询问菜单:
        [c]ompact  自动压缩(保留 2 轮)   ← compactAuto=true 时默认建议
        [r]ewind   回到早期检查点
        [k]eep     强行保留(下一轮请求可能被服务端 400 拒绝,风险自担)
```

**usage 双口径(联动)**:切换模型后历史 usage 累计与新模型无关——/context 分开显示:
- **会话累计 usage**(跨模型不重置,费用口径);
- **当前窗口占用**(estimateTokens vs 新窗口,预算口径)。

## 7. 壳层:命令族(CcGpt\Command\)

| 命令 | 行为 | 底座 |
| --- | --- | --- |
| `/context`(增强) | **双口径**:会话累计 usage(费用)+ 当前窗口占用(估算/窗口,百分比)/ 窗口上限 / 工具列表 | ContextBudget |
| `/model [id]`(增强) | 切换后执行 §6.1 对账三态(写入档案 → 重建 Budget → 超限菜单) | ModelSource + ContextBudget |
| `/compact [keep]` | 手动压缩:保留最近 keep 轮(默认 2),更早消息交 Compactor;压缩后 shell 自动 save session | Compactor + Conversation |
| `/rewind` | 列 userCheckpoints(摘要消息标记 [摘要],可选为截断点)→ 选序号 → truncateFrom(usage 不重置,文案明示"压缩前历史不可恢复") | Conversation |
| `/clear` | 删当前 session + reset + 生成新 sessionId | 已有 + Store |
| `/resume [id]` | 无参列出 sessions;带 id 恢复(当前未保存先提示) | Store |
| `/memory remember <text>` / `/memory forget <n>` / `/memory list` | 长期记忆管理(remember 后 setSystem 即时生效) | Memory + Conversation::setSystem |
| 自动压缩 | 每轮 run 前 needsCompact → 壳自动执行压缩(保留 2 轮)并提示;settings.compactAuto=false 关闭 | ContextBudget |

装配变化(bin/Application):壳持有 currentSessionId;ContextBudget(窗口 = 当前模型能力档案,无档案时 settings.contextWindow 兜底)、LlmCompactor、FileConversationStore(.runtime/sessions)、Memory(.work/memory.json)注入 Context;/context /compact /rewind /clear /resume /memory 六命令注册;/model 命令执行对账。
