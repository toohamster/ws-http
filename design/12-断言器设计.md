# 12 断言器细化设计(functional:Ws\Http\Assert)

> 层归属:**functional**。使用者:接口测试工程师、场景脚本作者。

**简单路径**:

```php
\Ws\Http\Assert\Watcher::create($response)
    ->assertStatusCode(200)
    ->assertBody('IS_VALID_JSON')
    ->assertJsonPath('$.result', 'eq', 0);
```

> 范围:Watcher(链式断言门面)、Comparison(操作符)、Assertion/AssertionResult(值对象)、与表达式引擎(design/13)的集成。
> 旧代码参考:`src/Ws/Http/Watcher.php`;需修复:B1(strpos 参数反)、B7(命名空间全局函数)、头断言大小写敏感;需新增:操作符全集、JSONPath 断言、结构化结果(供引擎收集)。

## 1. 双形态 API 设计

断言器有两个使用形态,共享同一套核心实现:

| 形态 | 使用方 | 失败行为 | 典型场景 |
| --- | --- | --- | --- |
| **流式(Watcher)** | 交互式使用者、PHPUnit 测试 | 立即抛 `AssertionException` | 手写 API 测试脚本 |
| **收集式(AssertionRunner)** | L3 自动化引擎 | 返回 `Support\ResultSet`(S7.5 通用容器),不抛 | 场景步骤后置断言 |

```
             ┌──────────────┐
   Response →│   Watcher    │→ 链式调用,失败即抛 AssertionException
             └──────┬───────┘
                    │ 内部构造
                    ▼
             ┌──────────────┐      ┌────────────────┐
             │ Assertion    │ ────→│  Comparison    │ 操作符实现(纯函数)
             │ (值对象)      │      └────────────────┘
             └──────┬───────┘
                    │
             ┌──────────────┐
             │AssertionRunner│→ AssertionResult[](收集式)
             └──────────────┘
```

## 2. Comparison:比较操作符全集

操作符为**契约化注册表**:`Comparison` 实现核心的 `Contract\ComparatorInterface`,内建操作符为默认注册项;业务方/plugin 可经 `Comparison::register(string $op, ComparatorInterface $impl)` 扩展自定义操作符(扩展成本 = 实现一个接口,不动核心代码)。默认集如下:

| 操作符 | 语义 | 类型规则 |
| --- | --- | --- |
| `eq` | 宽松相等后严格比较:数值型期望先转数值再 `===` | `"$expect"` 数字串可匹配数值字段(兼容 v1 中 expect 全为字符串的习惯) |
| `ne` | !eq | 同上 |
| `gt` / `ge` / `lt` / `le` | 数值比较;两侧均可数值化 | 非数值抛 ExpressionException(code:203) |
| `not_null` | 非 null 且非空串 | expected 忽略 |
| `is_null` | 为 null | expected 忽略 |
| `contains` | 字符串包含;数组 in_array 宽松 | — |
| `not_contains` | !contains | — |
| `starts_with` / `ends_with` | 前缀/后缀 | 字符串化后比较 |
| `matches` | 正则(preg_match) | 期望值为正则(含定界符) |
| `length_eq` / `length_gt` / `length_lt` | 字符串长度或数组元素数 | — |
| `type` | actual 类型属于期望:integer/double/string/boolean/array/null | — |

> v1 断言(仅 status/json + eq/gt/not_null)全部被上表覆盖;`not_null` 语义保留(修复 v1 中 expect 空串无意义的问题)。

数值化规则(决定 eq 的行为,需测试锁定):

```
normalizeEq($v): 若 is_numeric($v) → (string)转为规范数值字符串比较
                 否则原样字符串比较
例:expect "200" 匹配 actual 200 与 "200";expect "1.5" 匹配 1.5 与 "1.50"
```

### 2.1 Extension 机制:内部功能与外部注入的边界(S7.5)

functional 层的"内建集"只是**默认注册项**,机制上统一为可注入。区分两个概念:

| 概念 | 粒度 | 目的 | 例子 |
| --- | --- | --- | --- |
| **Extension** | 功能原子(一个接口实现) | 扩展能力本身 | 自定义操作符、XML 提取器 |
| **Plugin**(design/17) | 三方系统适配(认证+端点+语义化方法) | 面向业务场景的成品 | OpenAI/WordPress 客户端 |

- **注入入口**:操作符 → `Comparison::register(op, impl)`;提取 source → ExtractorInterface 注册(design/15 §3);HTTP 层 → RequestFactoryInterface(design/16);
- **闭包包装器**(core Contract 提供):`FnComparator` —— 用户的现成函数(本地函数或远程 API 封装)一行接入:
  ```php
  Comparison::register('decrypt_eq', new FnComparator(fn($actual, $expected) => decrypt($actual) === $expected));
  ```
- **远程函数约定**:Extension 内发起 HTTP 调用合法,但超时/失败语义自担(返回 false 即断言失败,**引擎不重试**);
- **不做**:命名空间前缀、版本协商、生命周期钩子 —— 注册表 + 接口就是全部机制(机制最小化)。

## 3. Assertion 值对象

```php
final class Assertion
{
    public function __construct(
        public readonly string $source,   // 'status' | 'json' | 'header' | 'raw_body' | 'time'
        public readonly string $path,     // source=json → JSONPath(design/13);其余为头名/空
        public readonly string $op,       // §2 操作符名
        public readonly mixed $expected,  // 期望值;not_null/is_null 忽略
        public readonly ?string $name = null,  // 断言别名(报告中显示)
    );
}
```

**actual 提取**(由 AssertionRunner 执行,不进 Comparison):

| source | actual 来源 |
| --- | --- |
| `status` | `Response->code`(int) |
| `json` | `ExpressionEvaluator::evaluate(Response->body, path)`;无匹配 → 断言失败(消息含路径) |
| `header` | `Response->header(path)`(大小写不敏感);缺失 → 断言失败 |
| `raw_body` | `Response->rawBody`(string) |
| `time` | `Response->totalTime()`(float) |

## 4. Watcher:流式断言门面

保持旧版链式 API 形态,方法签名与旧版一致处不赘述,差异点标注:

```php
final class Watcher
{
    public static function create(Response $response): self;
    public function setResponse(Response $response): self;

    public function assertStatusCode(int $statusCode): self;
    public function assertTotalTimeLessThan(float $seconds): self;    // 委托 time + lt
    public function assertHeadersExist(array $names): self;
    public function assertHeaders(array $headers): self;              // 关联=精确;索引=退化为 exist
    public function assertBody(string $expected, bool $isRegex = false): self;
    public function assertBodyJson(mixed $expected, bool $showDetail = false): self;
    public function assertBodyJsonFile(string $file, bool $showDetail = false): self;

    // 新增:JSONPath 断言(引擎/高级用法)
    public function assertJsonPath(string $path, string $op, mixed $expected): self;

    // 新增:收集模式(不抛异常,返回结果)——供引擎复用
    public function collect(callable $assertions): AssertionResult[]; // 内部捕获 AssertionException
}
```

### 4.1 各断言语义(与旧版差异以 ⚠ 标注)

| 断言 | 语义 |
| --- | --- |
| assertStatusCode | `code === statusCode` |
| assertTotalTimeLessThan | `totalTime <= seconds`(旧版消息文案有误导,重写) |
| assertHeadersExist | 每个 header 名 `HeaderBag::has`(大小写不敏感,⚠修复) |
| assertHeaders | 关联数组:头存在且值相等(值允许 `string[]`,任一匹配);索引数组:退化为 assertHeadersExist |
| assertBody | 特殊值:`IS_EMPTY`(rawBody === '')、`IS_VALID_JSON`(json_decode 成功);否则 **strpos($actual, $expected) !== false 包含匹配(⚠修复 B1,语义由"包含"明确定义,旧版行为不可靠)**;`$isRegex=true` 时 preg_match |
| assertBodyJson | `Response->body` 与 expected `==` 宽松比较;`$showDetail` 时消息附 var_export 双方 |
| assertBodyJsonFile | 读取文件、json 校验、`JSON_PRETTY_PRINT` 规范化后比较(⚠替换手写 prettyPrintJson/B7);`$showDetail` 附双方 |
| assertJsonPath | 构造 Assertion(source=json) → Comparison 求值 |

### 4.2 失败消息格式(统一模板)

```
Assertion failed [{name|序号}] {source}{path?} {op} {expected}
  expected: {expected 的可读表示}
  actual:   {actual 的可读表示}
  response: {method} {url} → {code} ({totalTime}s)     // 来自 curlInfo
```

- expected/actual:标量原样;数组/对象 `json_encode(JSON_UNESCAPED_UNICODE|JSON_PRETTY_PRINT)`;
- 异常 `code` 取 §错误码段(301–305 按断言类型),供程序化区分。

## 5. AssertionRunner:收集式执行(L3 使用)

```php
final class AssertionRunner
{
    /** @param Assertion[] $assertions */
    public function run(Response $response, array $assertions): AssertionResult[];

    public static function fromArray(array $raw): Assertion[];   // Schema v2 asserts 字段 → Assertion[](design/14 §5)
}

final class AssertionResult
{
    public readonly Assertion $assertion;
    public readonly bool $passed;
    public readonly ?string $message;   // fail 时按 §4.2 模板;pass 为 null
    public readonly mixed $actual;      // 实际值(报告用)
}
```

- **短路策略**:同一 Response 上依次执行全部断言,不短路(报告要展示所有失败项);单条断言内部的异常(路径无匹配等)捕获为 failed 结果,不中断;
- `run()` 返回 **`Support\ResultSet`**(S7.5):断言/提取/步骤/报告的统一消费容器(语义快捷 `passed()/failed()/toArray()`),CLI 与 Report 渲染统一走 `toArray()`;
- `fromArray` 映射规则见 design/14 §5(asserts 字段契约)。

## 6. 与旧版的行为差异清单

| # | 差异 | 原因 |
| --- | --- | --- |
| C1 | assertBody 包含匹配:旧的 `strpos($asserted, $body)` 反参 | 修复 B1 |
| C2 | 头断言大小写不敏感 | 修复 B8 |
| C3 | 删除 `isAssoc/prettyPrintJson` 全局函数 | 修复 B7;改用 JSON_PRETTY_PRINT |
| C4 | 新增 assertJsonPath / collect / AssertionRunner | 引擎需要结构化结果与路径断言 |
| C5 | 操作符扩展为全集(§2) | Schema v2 asserts 需要 |
| C6 | eq 数值化语义(字符串期望匹配数值字段) | v1 脚本 expect 全为字符串 |
| C7 | `IS_VALID_JSON` 改用 `json_last_error()` 判定 | 旧版 `json_decode($body) === null` 会把合法的 `null` 体误判失败 |
