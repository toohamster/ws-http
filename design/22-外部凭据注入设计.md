# 22 外部凭据注入设计(pause 步骤 + ValueSource 注册表)

> 层归属:**functional(Automated)**。使用者:场景脚本作者(需要在流程中途等待外部提供的值)、取值策略作者(注册自定义 ValueSource)。
> 背景:接口自动化中常见"流程进行到某一步,需要一个只有真实世界才能提供的值"(邮件/短信验证码、Authenticator TOTP、二次认证链接、人工审批结果),当前引擎(design/14–16)没有对应原语——extract 只能从 HTTP 响应提取,步骤类型只有 http/delay。
> 评审结论(设计讨论记录):统一模型 = **pause/resume 是流程维度,取值策略是数据维度**;原"交互输入/可编程等待/外部回调"三案收拢为一个步骤类型 + 一个策略注册表。跨进程挂起/恢复(自动化平台形态)列扩展预留,首版不背 Runner 序列化复杂度。

**简单路径**(场景脚本作者视角):

```json
{ "type": "pause", "var": "otpCode", "from": "stdin",
  "options": { "message": "请输入邮件验证码:" } }
```

```json
{ "type": "pause", "var": "otpCode", "from": "poll:email-otp",
  "options": { "interval": 5, "timeout": 300 },
  "extract": { "path": "$.data.code" } }
```

> 简单路径使用者不需要知道:ValueSource 如何注册、pending 如何判定、轮询如何调度。这些属于"复杂的事情必须可能"的部分,见 §2/§3。

## 1. 概念与边界

**两类等待,严格区分(防概念混用)**:

| 类型 | 语义 | 归属 |
| --- | --- | --- |
| **依赖等待**(dependency wait) | 等一个**必须的值**,拿不到流程无法继续 | 本文档:pause 步骤 |
| **节奏等待**(pace wait) | 值已到手,只是等服务端窗口/限频,纯延时 | 既有 delay 步骤(design/14),**不变、不并入** |

**pause 是什么**:

1. 一个**步骤类型**(`type: "pause"`):执行到此处流程挂起,从指定取值策略获得值,写入 VariableScope(design/15),继续后续步骤;
2. 一个**取值策略注册表**(ValueSource):`from` 字符串 → 策略实例;与 design/15 的 extract source 注册机制**心智相同但注册点独立**(一个面向"场景中途取值",一个面向"从当前响应提取")。

**pause 不是**:

- 不是数据驱动测试:场景开始前就备好整组输入、按记录迭代执行的需求归 design/23(Dataset),两者正交、互不依赖;
- 不是流程编排平台:不做跨进程/跨机挂起态序列化与外部回调 resume(列扩展预留);
- 不隐式等待:除 poll 策略自身外,引擎不引入任何隐式轮询/兜底延时。

## 2. 步骤契约(Schema v2 追加,detail 见 design/14 修订)

```json
{
  "type": "pause",
  "var": "otpCode",                    // 必填:取到的值写入的变量名
  "from": "stdin",                     // 必填:取值策略 id('stdin' | 'environment' | 'poll:<name>' | 自定义)
  "options": { },                      // 可选:透传给策略(策略自定义,含时间参数)
  "prompt": "请输入验证码",             // 可选:展示用说明(默认 "等待输入变量 <var>")
  "extract": { "path": "$.data.code" } // 可选:策略返回值是结构化数据时,经提取规则取最终值(语义同 design/15 extract)
}
```

校验规则(追加到 design/14 的 V 序列):

- **V11**:`type: "pause"` 必须带 `var`(非空字符串)与 `from`(非空字符串);
- **V12**:`from` 引用的策略在 Runner 装配时不存在 → 场景加载即失败(407);
- **V13**:`options` 若为标量/数组结构非法 → 402。

## 3. ValueSource 契约与内建策略

```php
namespace Ws\Http\Automated\Pause;

interface ValueSource
{
    /** 策略 id 前缀:'stdin' / 'environment' / 自定义名;'poll:<name>' 由 poll 包装器解析 */
    public static function id(): string;

    /**
     * 取值。
     * @param array $options 步骤 options 透传
     * @return ValueResult 一次性策略:立即返回 got/missing;可轮询策略:返回 pending 触发外层重试
     */
    public function fetch(array $options): ValueResult;
}

final class ValueResult
{
    public const GOT = 'got';           // 拿到值(value 生效)
    public const PENDING = 'pending';   // 暂未就绪(仅轮询语义;一次性策略不返回它)
    public const MISSING = 'missing';   // 确认没有(立即失败,不再重试)

    /** @param mixed $value */
    public static function got($value): self;
    public static function pending(): self;
    public static function missing(string $reason): self;
}
```

### 3.1 时间参数的归属(评审钉死的决策)

**pause 步骤本身零时间参数**。`interval`/`timeout` 只存在于"会调用外部接口、会反复尝试"的策略 options 里:

| 策略 | interval | timeout | 说明 |
| --- | --- | --- | --- |
| `stdin` | 不适用 | 无 | 人在场场景,卡住由操作者 Ctrl-C;一次性阻塞读取 |
| `environment` | 无 | 无 | 读一次即返回;需要"等一等再取"由脚本显式用 delay 表达,引擎不隐式轮询 |
| `poll:<name>` | **必需**(默认 5s) | **必需**(默认 300s) | 唯一调用外部接口的策略:interval 控制节奏(防服务端限频),timeout 上限转失败 |

### 3.2 内建策略

```php
final class StdinSource implements ValueSource        // id: 'stdin'
// options: { message: string, mask: bool(默认 false,回显为 *) }
// 行为:fgets(STDIN) 阻塞读取(trim);EOF(无输入流/CI 环境)返回 missing

final class EnvironmentSource implements ValueSource  // id: 'environment'
// options: { env: string(环境变量名) } 或 { file: string(文件路径,trim 首行) }
// env/file 均未配置或值不存在 → missing(立即失败)
// 值存在 → got

final class PollSource implements ValueSource         // id 前缀: 'poll:'
// 包装一个已注册的 extractor(复用 design/15 ExtractorInterface 注册表):
//   fetch: 按 interval 调用被包装 extractor → ValueResult
//     - extractor 有值 → 经步骤 extract.path 提取 → got
//     - extractor 无值(未命中)→ pending,等待 interval 后重试
//     - 超过 timeout → missing(reason 含超时时长与尝试次数)
// pending 期间的等待由 PollSource 内部 sleep 实现(Runner 无感知、无新状态)
```

- 为什么 poll 复用 design/15 的 extractor 注册表:验证码类场景的取值逻辑(从邮件 API/webhook 的响应里拿 code)与 extract 提取是同一套规则,不另造一套"取值 DSL";
- 自定义策略示例:短信平台轮询、测试平台取参、企业审批回调——实现 ValueSource 后经注册表注入。

### 3.3 注册与装配

```php
// 装配期(Runner 构造时,同 CookieStore 注入模式):
$runner = new Runner($http, new PauseRegistry([
    new StdinSource(),
    new EnvironmentSource(),
], pollExtractors: $existingExtractorRegistry));

// PauseRegistry:
final class PauseRegistry
{
    public function __construct(array $sources, ?ExtractorRegistry $pollExtractors = null);
    public function register(ValueSource $source): void;   // 重名 406(见 §5)
    public function get(string $id): ValueSource;          // 'poll:xxx' 特殊解析;未知名 407
    public function has(string $id): bool;
}
```

## 4. Runner 侧状态机(design/16 追加,不改主循环骨架)

```
执行到 Step(type=pause)
 → V 校验(var/from)
 → PauseRegistry 取策略(未知名 → 407,进 Report)
 → loop: result = source->fetch(options)
     got      → VariableScope::set(var, extract 处理后的值) → StepResult(status=passed) → 继续下一步
     missing  → StepResult(status=failed, reason) → 按 failFast 决定是否终止
     pending  → 仅 poll:内部 sleep(interval) 后重试,直至 timeout → missing
```

- StepResult 增加 `type: "pause"` 与 `from` 字段进 Report(JSON 报告契约追加可选字段,向后兼容);
- pause 失败(超时/missing)是**步骤级失败**,走既有 failFast 语义,不新增全局状态;
- 多个 pause 串行无特殊处理(逐个挂起取值);poll 策略阻塞期间进程只是 sleep,无并发诉求(扩展预留:并行场景)。

## 5. 错误码(400–499 引擎段追加)

| 码 | 含义 |
| --- | --- |
| 406 | pause 策略注册重名 |
| 407 | 未知名取值策略(from 引用不存在) |
| 408 | 取值失败(策略返回 missing:超时/不存在/EOF;reason 进 Report) |

(401–405 已被 design/13/14/15/16 占用;poll 的 timeout 本身不是异常,是 408 的 reason 之一。)

## 6. 测试要点

| 用例组 | 覆盖 |
| --- | --- |
| PauseRegistry | 注册/重名 406/未知名 407/`poll:` 前缀解析 |
| StdinSource | 输入流注入(fgets 可替换的流句柄)→ got;EOF → missing;mask 不影响值 |
| EnvironmentSource | env 命中/未命中;file 读取与 trim;两者都缺配置 → 402 校验 |
| PollSource(时钟可注入,sleep 替身) | extractor 首次有值 → got 立即返回;N 次 pending 后有值;超时 → 408 且尝试次数/reason 正确;interval 不 slept 足够则不重试 |
| Runner 集成(mock HTTP) | pause(passed)后变量可用于后续步骤(与 ${var} 替换打通);pause(failed)→ failFast;Report 中 pause 字段 |
| V11–V13 | Schema 校验三态 |

## 7. 与既有设计的衔接

- design/14(Schema):追加 pause 步骤类型与 V11–V13;
- design/15(变量):poll 复用 ExtractorInterface 注册表;pause 取到的值经同一 VariableScope 供 ${var} 替换;
- design/16(执行器):Runner 主循环新增 pause 分支(独立方法,不动 http/delay 路径);StepResult/Report 追加可选字段;
- design/23(Dataset):正交特性,互不引用;可组合(每条记录运行中遇 pause 各自挂起)。
