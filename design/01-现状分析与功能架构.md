# 01 现状分析与功能架构

> 基于对 `src/`、`tests/`、`README.md`、`composer.json` 的逐文件阅读。

## 1. 项目定位

**ws-http** —— 简单轻量的 HTTP 客户端工具库(基于 PHP cURL 扩展),定位:

- 发送 HTTP 请求的通用客户端(支持 SSL、Basic Auth、代理、Cookie、自定义请求头、常用 HTTP 方法);
- 可用于 **HTTP API 测试**(通过 Watcher 断言);
- 附带一个**基于 JSON 脚本的接口自动化测试引擎**(Automated 模块,半成品)。

技术栈:PHP >= 5.4(实际代码按 5.4 风格书写),仅依赖 cURL 扩展,PSR-4 自动加载(`Ws\Http\` → `src/Ws/Http`)。

## 4. 模块详解

### 4.1 Request(cURL 引擎,src/Ws/Http/Request.php)

**实例管理**:`Request::create($id = null)` 基于 `$id` 的单例池(`private $instances`),不传 id 则自动编号;构造函数私有。默认 `verifyFile` 指向内置 `_ssl/ca-bundle.crt`。

**配置类方法**(均为可链式/返回值风格):

| 分类 | 方法 | 说明 |
| --- | --- | --- |
| JSON | `jsonOpts($assoc,$depth,$options)` | 控制响应 JSON 解析行为 |
| SSL | `verifyPeer / verifyHost / verifyFile / getVerifyFile` | 默认开启 peer/host 校验,CA 用内置 bundle |
| 超时 | `timeout($s)` / `timeoutMs($ms)` | ms < 1000 时自动加 `CURLOPT_NOSIGNAL`(规避 PHP timeout ms bug) |
| 请求头 | `defaultHeaders / defaultHeader / clearDefaultHeaders` | 每次请求合并的缺省头 |
| cURL | `curlOpts / curlOpt / clearCurlOpts` | 缺省 curl 选项,`$new + $existing` 合并(新值优先) |
| Cookie | `cookie($string)` / `cookieFile($path)` | 字符串 cookie 或文件 cookie(FILE+JAR 同路径) |
| 认证 | `auth($user,$pass,$method)` | 支持 CURLAUTH_* 全系(BASIC/DIGEST/NTLM/ANY…) |
| 代理 | `proxy($addr,$port,$type,$tunnel)` / `proxyAuth(...)` | HTTP/SOCKS4/4A/5/5H,支持隧道与代理认证 |

**请求方法**:快捷方法 `get/head/options/connect`(参数进 query string)与 `post/delete/put/patch/trace`(参数进 body),最终都走 `send($method, $url, $body, $headers)`。`send()` 支持任意自定义方法(配合 `Method` 接口常量,如 `LINK`、`CHECKOUT`)。

**send() 内部流程**:
1. GET 之外:POST 设 `CURLOPT_POST`,其余设 `CURLOPT_CUSTOMREQUEST`;body 直接给 `CURLOPT_POSTFIELDS`;
2. GET 且 body 为数组:拼接到 query string(`buildHTTPCurlQuery` 递归拍平多维数组为 `a[b][c]` 形式,兼容 CURLFile);
3. 基础选项:RETURNTRANSFER、FOLLOWLOCATION(最多 10 次重定向)、HEADER=true、SSL 校验、`CURLOPT_ENCODING ''`(接受全部压缩);
4. 依次叠加:超时、cookie、auth、proxy;
5. `curl_exec` → 出错抛 `Ws\Http\Exception`;按 `$info['header_size']` 切分 header/body;
6. 返回 `new Response($info, $body, $header, $jsonOpts)`。

**辅助细节**:
- `getFormattedHeaders()`:defaultHeaders + 本次 headers 合并后小写化;无 User-Agent 补 `ws-http/1.0`;无 Expect 强制置空(避免 100-continue 延迟);
- `encodeUrl()`:parse_url 后重组,query 用 `getArrayFromQuerystring`(bin2hex 技巧处理中文 key)重新 `http_build_query`;
- 头部名一律转小写发送(`getHeaderString`)。

### 4.2 ARequest(静态门面)

全部为 static 方法,代理到 `Request::create('default')` 单例,提供 `Ws\Http\ARequest::get(...)` 这样的全局快捷用法。存在一处 **Bug**:`verifyHost()` 静态版误调用了 `verifyPeer()`(ARequest.php:38)。

### 4.3 Response

公共属性:`code`(int 状态码)、`curl_info`(getinfo 全量)、`headers`(解析后的关联数组)、`raw_body`、`body`(默认 false,仅当 Content-Type 含 `application/json` 且 json_decode 无错时填入解析结果,遵循 jsonOpts)。

`parseHeaders()`:优先用 PECL `http_parse_headers`,否则手写解析(支持同名多值 header 合并为数组、`\t` 续行、首行状态码存入 `$headers[0]`)。

### 4.4 Request\Body(请求体构造)

| 方法 | 产出 | Content-Type |
| --- | --- | --- |
| `Body::json($data)` | `json_encode` 字符串 | 使用方需配合 `application/json`(README 声明自动设置,实际**未**自动设置——见 §6) |
| `Body::form($data)` | `http_build_query` 字符串 | `application/x-www-form-urlencoded` |
| `Body::multipart($data,$files)` | 数组(文件转 CURLFile) | `multipart/form-data` |
| `Body::file($filename,$mimetype,$postname)` | CURLFile / `@file;type=;name=` 兼容串 | — |

### 4.5 Method

接口常量,收录 IANA HTTP Method Registry 全集(RFC7231/3253/2068/3648/3744/4437/4791/4918/5323/5789/5842),支持 WebDAV 与自定义方法。

### 4.6 Watcher(断言器)

`Watcher::create(Response)` / `setResponse()`,全部断言失败抛 `Ws\Http\Watcher\Exception`,通过返回 `$this` 支持链式调用:

| 断言 | 规则 |
| --- | --- |
| `assertStatusCode($code)` | int 相等 |
| `assertTotalTimeLessThan($t)` | 基于 `curl_info['total_time']` |
| `assertHeadersExist([...])` | 头存在性 |
| `assertHeaders([...])` | 关联数组精确比对(值可为数组→in_array);传索引数组时退化为 assertHeadersExist |
| `assertBody($x,$regex)` | 特殊值 `IS_EMPTY`(空体)、`IS_VALID_JSON`;否则 strpos 包含(注:此处**有 Bug**,`strpos($asserted, $body)` 参数顺序反了,应为 `strpos($body, $asserted)`,导致断言恒失败/恒成功错乱);`$regex=true` 时按正则匹配 |
| `assertBodyJson($obj)` | raw_body json_decode 后 `!=` 宽松比较,可选 var_export 详情 |
| `assertBodyJsonFile($file)` | 与期望 JSON 文件比对,内置手写 `prettyPrintJson()` 美化后比较 |

文件末尾定义了两个**全局函数** `isAssoc()` / `prettyPrintJson()`(挂在 Ws\Http 命名空间,靠 PHP 的 fallback 机制被调用)。

### 4.7 Automated(接口自动化测试引擎,半成品)

**目标形态(从 example.json / postmanv1.json 可还原)**:以 JSON 描述一个"业务场景脚本"(如:登录 → 取 token → 查门店 → 下单),脚本含:

- `vars`:变量表,请求中用 `${varname}` / `$varname` 占位,`Task\Body::varReplace()` 递归 str_ireplace 替换;
- `requests[]`:每项 `type=1` 为 HTTP 请求(method/url/headers/authorization/proxy/timeout/dataMode/data),`type=2` 为延时(sleep 秒);
- `postProcessors`:① `setVar` 从响应(JSON path 如 `list[0].xktvid`、或 header)提取值回写变量;② `asserts`(status/json 断言,eq/gt/not_null 等)。

**已实现**:
- `Task::parse($json)` → `Task\Body::parse()` → `Task\Request::parse()` 三层对象化;
- `Task\Request` 解析:dataMode 支持 `params` / `urlencoded` / `raw-json` / `raw-xml` / `raw-textxml` / `raw-html` / `raw-text`(`raw-binary` 抛异常),自动补 Content-Type;authorization 支持 Basic(其余方式直接把 `authorization.body` 塞进 Authorization 头);timeout 支持 `"15s"` / `"15 ms"` 字符串解析(默认 30s);proxy 类型映射 CURLPROXY_*;
- `Bootstrap::runTask()`:遍历 requests,延时项 sleep,请求项执行 `doRequest()`(创建 Request、应用 auth/proxy/timeout、varReplace 后发送)。

**未实现/半成品**:
- `Bootstrap::run()` 为空,无 CLI 入口;
- 执行循环里 `break` 硬编码(Automated/Bootstrap.php:52)——**实际只执行第一个请求**;
- `postProcessors`(setVar 提取、asserts 断言)在 JSON 中已定义但解析代码完全未处理(代码中留有"设置断言规则""设置变量提取规则"注释);
- Task `$type`(1 关联业务:任一请求失败即终止 / 2 非关联)字段有定义、无消费逻辑;
- `CookieStore` 为空壳类;
- `Task\Request::setAuthorization()/setProxy()` 的判断条件写反:`!empty($x) && empty($x['type'])` 中 `empty` 应为 `!empty`,导致**配置了 auth/proxy 也永远不会生效**(Automated/Task/Request.php:173、228)。

### 4.8 测试

`tests/bootstrap.php` 为自研极简测试器:依赖外部包 `\Ws\Env::dump()`(output 函数)和 `ITest` 接口,**不属于本库**,重构时需替换为 PHPUnit。用例覆盖:认证 401、GET 断言(头/体/正则/总耗时)、POST 201、JSON 断言、JSON 文件比对、代理(Lantern 本地代理)等;另有 Autohome 爬虫作为真实业务使用样例(GBK→UTF8、递归抓取、限速)。

## 5. 依赖与兼容性现状

- 运行依赖:ext-curl、ext-json(显式检查)、ext-openssl(SSL);可选 PECL http(`http_parse_headers`);
- `composer.json`:`php >= 5.4`,无 require-dev,minimum-stability dev;
- PHP 5.4 风格:`array()` 混用 `[]`、无类型声明、无可见性常量、类常量接口等。

## 7. 保留价值 vs 应淘汰

**保留(重写)**:cURL 封装的配置模型(auth/proxy/ssl/timeout/cookie/默认头/自定义 curl 选项)、Response 结构、Watcher 断言语义、Body 构造器、Method 常量、Automated 的 JSON 脚本设计(变量/提取/断言/延时编排思路)。

**淘汰/替换**:
- PECL http 依赖与 `@` 风格兼容代码(PHP7.4 下 CURLFile 恒存在,`curl_file_create` 分支可删);
- 手写 prettyPrintJson(用 `JSON_PRETTY_PRINT`);
- 自研测试器(换 PHPUnit 9);
- `\Ws\Env` 外部依赖、遗留调试代码;
- 内置 ca-bundle.crt(10 年前的旧证书,改用系统 CA 或提示配置)。
